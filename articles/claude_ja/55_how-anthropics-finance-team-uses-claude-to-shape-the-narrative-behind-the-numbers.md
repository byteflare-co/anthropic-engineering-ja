# Anthropic のファイナンスチームが、数字の背後にあるナラティブを Claude でかたちにしている方法

ファイナンスにおける仕事は、数字の背後にあるストーリーをかたちにすることです。重要な指標がなぜ動いたのかを説明し、市場のトレンドに基づいて期待値を設定し、財務結果をプロダクト戦略に結びつける。ところが現実には、数字が合っているかを確かめることだけに大半の時間を費やしてしまいがちです——図表が再び更新されたあとに、4 回目のデッキ読み直しをしている——その数字が何を意味しているかを考える代わりに。

たとえば、私はチームが CFO のために用意する四半期ごとの取締役会デッキに入れる分析と指標の集計を担当しています。通常、デッキが出来上がるまでに、私は何度も改訂をかけることになります。数字はデッキを出す当日の朝まで更新され続け、更新のたびにコメントは最新の数字と照らし合わせて確認しなければなりません。さらに、デッキは共同作業で、パートナーが自分の担当スライドを同時に更新しています。更新が入るたびにナラティブ全体をベースラインから引き直すことになります。スライド 4 のコメントは、まだスライド 17 の数字と整合が取れているか？ 誰かが定義のないまま指標を持ち込んでいないか？ ストーリーが依然として一貫していることを確認するために、私はデッキ全体を読み直し続けなければなりませんでした。

Claude は今、これらすべてを私の代わりにやってくれます。仕事の足元にあるインテグリティ層を Claude が支えてくれるので、私の時間はその上に乗るナラティブに向けられます。Claude は私の月次レビュープロセスやモデル監査の一部にもなっており、その分の時間は、チームとのコラボレーションや、創造的な思考、そして判断を必要とするファイナンスの部分に振り向けられるようになりました。

## 動きの速いビジネスを俯瞰する

私は 2025 年 3 月に Anthropic のコーポレートファイナンス＆ストラテジーチームに加わりました。コーポレートファイナンスはファイナンス組織の中心に位置しています。他のファイナンスチームはビジネス側と直接組んで動いており——たとえば go-to-market ファイナンスはセールスと——彼らが学んだことはすべて私たちに還流してきます。私たちの仕事は、CFO と取締役会が見る必要のあるナラティブを準備することです。売上はどう推移したのか、マージンには何が起きているのか、キャッシュはどう配分されているのか、そしてそれが年度の残りにとって何を意味するのか。

そのナラティブは、足元でビジネスが変化し続けるなかで一貫性を保たなければなりません。Anthropic では、それはプロダクトのローンチ、モデルのローンチ、価格変更、セールス活動のセグメント分けの転換などを意味し、しばしば同じ週のうちに同時に起こります。コーポレートファイナンスは会社の変化のフルレートをすべて吸収し、それでも取締役会に成立するストーリーを手渡さなければなりません。

## 私が Claude をワークフロー全体でどう使っているか

私は [Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) と [Claude for Excel](https://support.claude.com/en/articles/12650343-use-claude-for-excel) を並行して使っています。Claude Cowork はドキュメントやデッキにおける執筆と情報の統合を助けてくれ、Claude for Excel は財務モデルの中で Claude に直接編集してもらうために使います。

先ほど触れた取締役会デッキの作業では、ファイルを Claude Cowork に渡し、すべての数字と主張が単一のソース・オブ・トゥルースに整合していることを検証するよう依頼します。さらに、取締役のような読み手がナラティブを読むときの目線でも読んでもらい、矛盾している箇所や、読者が持っていないコンテキストを前提にしている箇所をフラグしてもらいます。Claude は私が見逃しがちなものを捕捉してくれますし、それを数字が動くたびに、一度きりではなく毎回やってくれます。

もうひとつの例は、私たちの月次財務レビューです。これは月ごとにタブを切った Google Doc で、フォーキャストに対する変動分析として構造化されています。ある月について書き始める準備が整ったら、私はモデルから関連する財務テーブルをドキュメントに落とし込み、補足コンテキストへのリンクを貼り、Claude Cowork に対して、私たちが既に使っている語り口で初稿を書くよう依頼します——売上は A に対して B、ズレは C%、ドライバーは D、というふうに。私はそこから編集します。月ごとの語り口の一貫性は数字と同じくらい重要で、Claude は前月のドキュメントを参照させればそれを成し遂げてくれます。

Claude と私たちのプロダクト群が進化するにつれて、私の働き方も進化します。たとえば Claude for Excel は、タブをまたいだ参照を追えなかった頃から、バランスしないバランスシートを複数のタブをまたいで追跡し、根本原因を見つけられるところまで到達しました。初めて見るモデルを開いたときには、自分が時間を投じる前に、主要なドライバーを要約し構造的な問題をフラグするよう Claude に依頼します。

こうしたワークフロー全体——取締役会資料におけるナラティブの整合性、Sheets と Excel でのモデル診断、Claude Cowork での初稿コメント——を通じて、私は本当に判断を要する仕事——フレーミング、シナリオに関する問い、そしてフォワードルッキングな分析——にそのまま振り向けられる時間を取り戻しています。

| ワークフロー | ケイデンス | ツール | Claude のはたらき |
| --- | --- | --- | --- |
| 取締役会デッキ | 四半期 | Claude Cowork | スライド間で数字を突合し、ナラティブの一貫性をチェック |
| 月次財務レビュー | 月次 | Claude Cowork | 確立された語り口で初稿コメントを起草 |
| 財務モデル作業 | 必要に応じて | Claude for Excel | タブをまたいだ参照を追跡し、モデルの問題を診断 |
| クロスチームのコンテキスト | 継続的に | Google Workspace と Slack のコネクター | ドキュメント、メール、Slack から意思決定と理由を引き出す |

## コンテキストがすべてを成り立たせている

Claude Cowork が機能するのは、私と同じコンテキストを Claude も見ているからです。チームのナレッジソースのうちいくつかを挙げれば、ドキュメントやローカルファイル、メール、そして Slack です。重要なドキュメントに出会ったら、私はそれをプロジェクトメモリにコミットします。クロスファンクショナルな長いスレッドの中で意思決定がなされたら、その結論と理由を Claude に引き出してもらい、次にそのトピックが取締役会サイクルで浮上したときに手元に置けるようにします。

私はまた、対象オーディエンスごとにプロジェクトを分けています。月次レビュー用にひとつ、取締役会デッキ用にひとつ。トーンと慣習が異なるので、メモリも異なり、Claude はそれに応じてコンテンツを生成します。

## ファイナンス組織全体での Claude Cowork

財務組織全体で、私の同僚たちは Claude Cowork に [金融サービス向けプラグイン](https://www.anthropic.com/news/finance-agents) として現在パッケージされている多くの [skill](https://support.claude.com/en/articles/12512180-use-skills-in-claude) を使っています。CFO 組織が今日 Claude Cowork をどう使っているか、いくつかの例を挙げます。

- **ファイナンス＆ストラテジー:** アナリスト自身がプロンプトから組み立てる、インタラクティブなフォーキャストとコホートダッシュボード。SQL もエンジニアリングの介在も必要ありません。日次の売上と指標のダイジェストが、リーダーシップの Slack に朝 7 時に届きます。
- **アカウンティング:** GL と補助元帳、銀行口座の照合。差異が分類され、レビュアーコメントは初稿として起草されます。フラックス（変動分析）は 3 つの財務諸表すべてで実行されます。チームの誰もが Slack で Claude に質問を投げ、出典付きの回答を得られます。
- **コーポレートディベロップメントと IR:** 1 日に 3〜4 件の買収候補に対するスクリーニングレポートを、メモと公開データから組み立て、数分のうちにメモへロールアップします。チームの時間は判断と意思決定そのものに使われ、初稿の作成には使われません。
- **タックス＆トレジャリー:** 移転価格、R&D クレジット、ネクサスに関する問いに、一次ソースの引用付きで回答します。間接税とキャッシュの照合は、アカウンティングと同じ skill パターンで動きます。

## Claude を使い始めるファイナンスチームへのアドバイス

私が 1 年前に Anthropic に加わった頃、AI ツールはほとんどが LLM でした——テキストは得意でも、数字は得意ではない。私を引き込んだのは、Claude for Excel が進歩していくのを目の当たりにしたことでした。モデルが良くなるにつれて、その違いを文字どおり追いかけられるのです。

迷っているのであれば、シンプルなところから始めてください。Claude にドキュメントを読ませて要約してもらう。そこから限界を押し広げ続けるのです。Claude は繰り返し起こるワークフローで最も価値を発揮します——取締役会サイクルや月次レビューがそうで、ここでは一貫性が複利的に積み上がり、プロジェクトメモリも回を重ねるごとに豊かになっていきます。手の込んだスタックは要りません。私はほぼ Claude Cowork [プロジェクト](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork)、Claude for Excel、そして Google Suite Connector だけで動かしています。

そして、どの Claude のサーフェスを使えばよいか分からなければ、Claude に訊いてみてください。Claude をループに入れておけば、私は仕事の足元で進む変化のペースに追いつけます。インサイトにより速く到達でき、サプライズやボトルネックは減り、フレーミングとフォワードルッキングな分析により多くの時間を充てられます。

*今日から* [*Claude Cowork*](http://claude.com/cowork) *を始めましょう。*
