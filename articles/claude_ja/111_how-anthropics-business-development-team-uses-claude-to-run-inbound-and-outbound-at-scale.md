# Anthropic のビジネス開発チームが Claude を使ってインバウンドとアウトバウンドを大規模に回している方法
- 執筆者

  John Albert

ビジネス開発でのキャリアの初期、アカウントエグゼクティブたちは何百ものアカウントが並んだリストを私に渡してきて、私は各社を一つひとつ調査し、適切な連絡先を見つけ、メールアドレスを探し出し、アウトリーチ文面を起草しなければなりませんでした。インバウンド側も同様に、手作業で時間のかかるワークフローでした。

昨年の夏 Anthropic に入社したとき、私はセールスの受信箱を管理する役割を引き継ぎました。1 日あたり約 5 時間を費やして、見込み客からのインバウンドの関心に手作業で返信し、自分の担当アカウント群の管理と並行して、しばしば同じような、あるいは似たような製品に関する質問に答えていました。

今では、そうした作業の多くが [Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) 上の skill とスケジュールされたタスクとして組み立てられています。パーソナライズされた顧客向けメールは下書きとして用意され、私はそれを送信前にレビューし、カスタマイズするだけです。アウトバウンドの作業は、以前は何時間もかけてまとめていた詳細なリサーチから始まりますが、今はその時間をかける必要がありません。

その結果、私やチームメイトたちは、手作業で反復的な仕事に費やす時間を減らし、本当に重要なこと——お客様を助けること——により多くの時間を使えるようになりました。

以下は、Claude Cowork が Anthropic のビジネス開発機能をどのように底上げし、戦略的な仕事や顧客の課題の理解、Claude がその課題をどう解決できるかをお客様に伝えることに、より多くの時間を割けるようにしているかについてです。

## **管理業務と反復作業の自動化**

BDR（ビジネス開発担当者）はセールスプロセスの起点に立ち、インバウンドの需要を見極め、事業のためのアウトバウンドパイプラインを構築します。Anthropic では、こうした動きは今やまず Claude Cowork を通じて行われます。

私たちのインバウンド体制の基盤となっているのが、セールスの受信箱で最もよく受け取る質問と、それに対する最良の回答をまとめたドキュメントです。このドキュメントはセールスのナレッジベースとして機能し、Claude は返信を起草する前に必ずこれを読みます。このドキュメントの作成は Claude が手伝ってくれました（関連する情報源を指し示すだけでした）。そして今では、情報が古くなっている可能性をフラグ立てすることで、ドキュメントが最新であるかどうかを継続的に検証してくれており、ユーザーはそれを検証できます。

このドキュメントを土台にした最も重い処理を担うのが、1 時間ごとに実行される受信箱 skill です。担当者の受信箱をスキャンし、返信が必要なすべてのスレッドを見つけ出し、担当者が読み、編集し、送信できる返信案を作成します。この skill は、簡潔なシステムプロンプト、コンテキストとしてのナレッジベース、そして担当者の文章スタイルのプロファイル（これも私たち各自が、自分が書いたドキュメントやメッセージ、メールを読み込む voice skill を使って作成します）から成り立っています。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a769d842080f00d799fb656_07-skills-panel.png)

*受信箱 skill は、簡潔なシステムプロンプト、製品情報の情報源としてのチームのセールスナレッジベース、そして各担当者向けにカスタマイズされた voice プロファイルの上で動作します。*

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a766c160d2ae2a65100738d_06-customer-email-drafter.png)

*受信箱 skill は担当者の受信箱をスキャンし、レビュー用の下書き返信を残します。このプレビュー内のすべての情報は、公開にあたって匿名化されています。*

私はまた、管理業務の負担を軽減する 2 つの軽量な skill も活用しています。すべての BDR は、ミーティングの無断欠席や見込み客が音信不通になることの辛さを知っています。これに対処するため、私は Gmail と Google カレンダーを監視し、そうした事態が起きたときに通知してくれる skill を作り、素早くフォローアップできるようにしました。

もう一つの skill は、私たちの CRM コネクタを使ってすべての新規リードをスキャンし、パーソナライズされた最初のタッチを起草します。この skill は 1 日を通してスケジュールに沿って実行され、リードを待たせないようにしています。

さらに、Salesforce を最新の状態に保つ skill もあります。商談ステージに関する社内ガイダンスを読み込み、それを Gmail や Gong で実際に起きていることと照合します。もし顧客とミーティングを行い、価格の話に進んでいるなら、その商談はおそらく次のステージへ進むべきです。Claude は根拠とともに各 Salesforce の更新案を提示し、承認を待ちます。私が提案を編集または却下すると、Claude はその理由を記録し、同じ間違いを繰り返さないようにします。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a7a595ba53cbb60ea8f0055_pipeline-scanner-demo-run.png)

*パイプラインスキャナー skill は、担当者による承認のために Salesforce の更新案を提示します。ここではデモデータを用い、すべての情報を公開にあたって匿名化して示しています。*

## **アウトバウンドと収益に関わる業務の最適化**

私は平均して、常時 100 を超えるアカウントを担当しています。これをすべてカバーできているのは、夜間にスケジュールされたタスクとして実行される skill のおかげです。この skill は私の担当領域全体を巡回し、各アカウントの現状——例えば誰と連絡を取っているか、Claude を今どのように使っているか、どのようなシグナルが関連しているか——を観察します。これを実現するために、Claude は Salesforce、Apollo や Common Room といったセールスツール、Gong、そして私たちのデータウェアハウスに接続し、深いリサーチを行い、私たちのチームが精査したアウトバウンドガイダンスと ICP 基準に照らして検証します。

この skill のこうした要素が、Claude が Anthropic の BDR のように働くための助けとなるコンテキストを加えています。朝、Claude Cowork を開くと、各アカウントについてのブリーフ、スコア、そしてアウトバウンドの打ち手が用意されています。

このワークフローは時間とともにますます有用になっていきます。各 BDR が Claude の結果にフィードバックを与えることができ、それが skill にフィードバックされていくからです。この skill は小さなメモリファイルと台帳を保持しており、反復的で重複した作業を防いでいます。

このリサーチはフォローアップの会話で活用され、私たちのアウトリーチはより的確なものになります。顧客と話すとき、私たちは彼らのビジネスについて十分な知識を持ち、より深い戦略的な議論を行えるだけ課題に近づいています。

ディスカバリーコールも、Claude を使って改善に取り組んでいるアウトバウンドの動きの一つです。私たちは、Gong の文字起こしをディスカバリーコールのプレイブックと照合し、各コールについてのスコアカードを作成する skill を使っています。フィードバックには、うまくできた点トップ 3、改善すべき点トップ 3、基準に照らした明確な合格・不合格の判定、そして次に練習すべき最もレバレッジの高い一点が含まれます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a76a1686073481f44901a90_02-bdr-call-coach.png)

*コールコーチ skill は、私たちのディスカバリーコールについてのスコアカードと、それを改善するための具体的な提案を提供します。ここではデモデータを用い、すべての情報を公開にあたって匿名化して示しています。*

## **単発の依頼を効率化する**

BDR チームに寄せられる依頼はしばしば場当たり的なものですが、Claude のおかげで、私たちは AE とより戦略的に連携できるようになりました。AE がある主要アカウントの利用トレンドについて知りたいと言えば、プロンプト一つで、関連するトレンドを分かりやすく説明的に示すダッシュボードを提供できます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a76a1c80fce7dcd2bc87af1_01-spend-trends.png)

*ターゲットアカウント向けに生成された支出分析レポート。*

Claude とのデータ分析・レポーティング作業は、アウトバウンドの仕事にも活きています。私のお気に入りのワークフローの一つが、未発見の利用状況を洗い出すプロンプトの実行です。AE の担当アカウント全体を対象に、まだセールス上の商談が存在しないアカウントレベルの利用シグナルを見つけ出します。これは多くの場合、顧客に対してアウトリーチを開始し、Claude の利用状況や体験を最適化するために協働を始める絶好のシグナルとなります。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a76a2045602baca070bfcb8_05-undiscovered-usage.png)

*ある AE の担当アカウントに対する製品志向の一斉調査により、対応する商談のない、すでに製品を利用しているすべてのアカウントが返される。公開にあたってデモデータを用い、すべての情報を匿名化または改変している。*

私たちはイベントのアウトリーチにも Claude を活用しています。ある AE から、近日開催予定の [Claude Code for Data Engineering](https://www.anthropic.com/webinars/claude-code-for-data-engineering) ウェビナーについて、興味を持ちそうなアカウントを自分の担当領域から見つけてもらえないかと相談されました。そのための skill は持っていませんでしたが、この種の依頼であればプロンプト一つで十分でした。Claude は担当領域全体の利用データと CRM の履歴を確認し、各アカウントを私たちの ICP に照らしてスコアリングし、招待する価値のある連絡先とともに最も適したアカウントをフラグ立てしました。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a7a59ce7be09b7abd674db9_river-email-drafts.png)

*ウェビナー招待に適したアカウントを見つけるよう依頼されると、Claude は担当領域全体を調べ上げ、各アカウントをチームの理想の顧客プロファイルに照らしてスコアリングする。*

こうした skill やスケジュールされたタスク、そして私たちが精査してきたコンテキストが組み合わさることで、Claude は常時稼働のビジネス開発パートナーになります。

## **Claude Cowork を始めるビジネス開発チームへのアドバイス**

以下は、ビジネス開発チームが Claude Cowork を使い始める際のいくつかのヒントです。

- **ワークフローより先にナレッジベースを構築する。** チームが繰り返し答えている質問と、その最良の回答を、外部向けの一つのドキュメントに集約しましょう。手作業で書く必要はありません。関連する製品ドキュメントやチームのチャンネルを Claude に指し示せば、最初のバージョンを作ってくれます。
- **チームの働き方の実例を Claude に与える。** Claude は与えられたコンテキストに基づいて下書きを作成します。アウトバウンドであれば、うまくいったメッセージの例や理想の顧客プロファイルを含めることができます。各担当者は自分の文章スタイルを Claude に学習させることもでき、下書きが送信者らしい文面で届くようになります。
- **すべての送信に人を介在させる。** Claude は下書きを生成できますが、私たちは今も読み、編集し、送信しています。
- **skill をチーム全体で共有する。** 私たちのチームは、最もよく使う skill を共有プラグインに保持しており、担当者が日常業務で継続的に使っていることが確認できた skill を、そこに昇格させています。
- **skill をチーム全体の働き方に適応できるだけ汎用的にする。** 担当領域、アカウント群、ワークフローは担当者ごとに異なるため、共有 skill は一人のルーチンに限定せず、適応できる程度に汎用的に保っています。
- **フィードバックを skill に書き戻す。** hook を却下したり下書きを修正したりしたときは、その理由を skill に記録させ、同じ間違いを繰り返さないようにしましょう。

私からの一番のアドバイスは、とにかく試してみることです。与えるコンテキストとツールが多いほど、できることは増えていきます。
