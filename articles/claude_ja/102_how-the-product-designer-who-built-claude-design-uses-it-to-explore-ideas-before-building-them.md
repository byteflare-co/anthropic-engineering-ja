# Claude Design を作ったプロダクトデザイナーが、作る前にアイデアを探るためにそれをどう使っているか

2025 年秋、私は [Claude Code for VS Code](https://code.claude.com/docs/en/vs-code) 唯一のプロダクトデザイナーとして、エンジニア 2 人と共に、Claude Code が行うすべてのことをターミナルの外側にあるフレンドリーなインターフェースとして作り直す仕事をしていました。9 月末に[ベータ版を出荷し](https://www.anthropic.com/news/enabling-claude-code-to-work-more-autonomously)、11 月には[Opus 4.5 が登場し](https://www.anthropic.com/news/claude-opus-4-5)、Claude Code チームは速く、そして積極的に出荷し始めました。エンジニアたちはそれまでよりはるかに多くのものを出荷するようになった一方で、私はずっと以前と同じペースで作業を届けていました。私には追いつく方法を見つける必要がありました。

Claude Code はターミナル上で動き、そこではすべてがテキストベースです。私の最初の試みもそのように扱ったものでした。出力をコピーして Claude に貼り付け、スクリーンショットを添えて、「これが追加したい機能です。デザインしてもらえますか?」と尋ねたのです。結果は芳しくありませんでした。サイドプロジェクトとして 1 か月ほど、私は Claude のデザイン出力を改善する方法を探し続けました。

## **Claude に HTML の遊び場を与える**

やがて答えにたどり着きました。Claude は HTML が本当に得意なのです。私たちは HTML をウェブサイトのためのフォーマットだと考えがちですが、それは豊かでインタラクティブなビジュアルメディアでもあります。スライドデッキ、動画ファイル、PDF で作れるものは何でも、ウェブページでも作れるのです。そこで私は Claude に HTML を作らせるようプロンプトし、左でチャットし右で出力を見られる分割ビューのインターフェースを与えました。

それは役に立ちましたが、プロダクトデザインは自分が携わる製品とブランドについての知識を応用することで成り立つものです。そこで次のステップとして、Anthropic のブランドの本質(私たちの製品が使うフォント、色、アセット、原則)をプロンプトへと蒸留する作業にしばらく取り組みました。こうすることで、ツールにプロンプトを入力すると、出力が Anthropic のブランドガイドに準拠するようになります。

そのすべてを小さな社内プロトタイプにまとめ、チームに共有しました。プロダクトデザイナーたちはすぐにそれをインタラクティブなプロトタイプ作りに使い始めました。従来のデザインツールでクリックスルーのプロトタイプを作るには、すべての画面のすべての状態をモックアップし、手作業で結びつける必要があります。ここでは、自分のアセットを Claude に渡して「動くようにして」と言うだけです。Claude が届けるアーティファクトにはすべて、ドキュメントを共有するのと同じように共有できるリンクが付いています。

## **Claude Design がビジュアル作業のためのメディアになるまで**

Claude Design がどれほど魅力的かを最初に実感したのは、[Anthropic Labs](https://www.anthropic.com/news/introducing-anthropic-labs) チームのオフサイトで行われたアイデアピッチセッションでした。その場にいた全員が、多くの場合は自分の発表の番が来る直前のミーティングの最中に、それを使ってスライドをまとめ上げていたのです。そのセッションが Labs チームに人員を配置する決め手となり、Claude Design はサイドプロジェクトから本格的なプロジェクトへと変わりました。

私たちはそれをプロダクトのモックアップのためのツールと表現するのをやめました。Claude Design は、あらゆる種類のビジュアルコミュニケーションを生み出すツールになったのです。スライドデッキ、ランディングページ、PDF として印刷するワンページャー、メール、アニメーション、SNS で共有するビジュアルなど。私はそれを、プロダクトデザインより一段上にあるものだと考えています。つまり、伝達とアイデア出しを主な目的とするビジュアルについて Claude と協働するということです。

モデルの視覚能力が向上するにつれて、Claude Design がこなせる作業の幅と質も向上していきます。私たちの最新の Opus クラスモデルである [Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) は、あなたが渡すチャート、図、スクリーンショットの読み取りが上達しており、Claude Design と組み合わせることでプレゼンに耐えるデッキやメモを作る強力な力となります。

## **Claude Design がやることを意図していないもの**

Claude Design は画像モデルを持たず、画像生成のために作られたものでもないため、ロゴデザインには向いていません。それでも試す人が後を絶ちませんが。ここでの正しいアプローチは、すでに持っているロゴやアセットを持ち込むことです。製品の残りの部分も同じように動作します。Claude は選択肢や出発点を作り、あなたが白紙のキャンバスを前に立ち尽くさなくて済むようにします。そして何が良いかを、単体で、あるいは複数のバージョンを組み合わせて選ぶのはあなたです。

そして本番のソフトウェアを出荷しようとしているなら、Claude Code を使い続けてください。Claude Code はコーディングのためのものであり、Claude Design はデザイン作業のそれ以外の部分、つまり初期のアイデア出し、コラボレーション、誰も構築にコミットする前に方向性への賛同を得ることのためのものです。この 2 つは往復しながら連携して働きます。Claude Code で始めたプロトタイプを Claude Design に同期してキャンバス上でイテレーションと編集を行うことも、Claude Design で構築の準備が整ったプロトタイプを Claude Code に引き渡すこともできます。モデルが本番ソフトウェアの構築が上達するにつれて、最も重要になる作業はプロセスのより早い段階へと移っていきます。つまり、良いアイデアを持つこと、全員の足並みを揃えること、そしてアイデアがまだ初期段階のうちにフィードバックを集めることです。

## **私が日々の仕事で Claude Design をどう使っているか**

私は毎日、いわゆる基本的なデザイン作業のために Claude Design を使っています。初期のアイデアをワイヤーフレーム化したり、同僚からフィードバックを集めるためにあるフローの 15 通りのバージョンを生成したりといった具合です。私自身の仕事から最近の例をいくつか紹介します。

- **Claude Design のイントロアニメーション。** Claude Design にサインアップしたときに流れるあのアニメーションは、ツール自体の中で作られましたが、直接的にではありません。私はアニメーターではないので、まず Claude Design に専用のビデオエディタを作らせ、そのエディタを使ってアニメーションを作りました。

- **地下鉄の時刻表アプリ**で、動きの物理演算を調整するためのアニメーションコントロールを付けたもの。

- **Instagram 風のカラーコントロール。** 色を言葉で説明するのではなく、スライダーとプリセットでアプリのカラースキームを調整できるように Claude に頼みました。

- **Claude Design 自体のリデザイン。** チームメイトの Helen と Andrew、そして私の 3 人で、ツールの中でエディタの新しいデザインについて構想を練り合っています。これをそのまま出荷することはありませんが、プロダクトが何になり得るかを探るための方法です。

## **Claude Design を使う上でのベストプラクティス**

1. **プロンプトを打つ前に考えを済ませておく。** 自分のビジョンに合った出力を最も効率よく得る方法は、必要なことを事前に Claude に伝えることです。私はデザインする前にプロンプトを書くことに多くの時間を費やします。時には Claude Design の音声ボタンでプロンプトを口述することもありますし、ソファでスマートフォンのメモアプリに入力したり、散歩中にボイスメモを録音して後で文字起こしを貼り付けたりすることもあります。どのコミュニケーション方法を好むにせよ、パソコンから離れているうちに何が欲しいかを固めておけば、机に向かったときに Claude があなたの正確なビジョンを実行できます。
2. **どんな見た目にすべきかを Claude に伝える。** 何も指示しないと、Claude はお気に入りの美学の一つを選びます。[あなたもきっと見覚えがあるはずです。](https://www.newyorker.com/the-ai-design-aesthetic-thats-taking-over-the-internet) フォントと色を指定したり、インスピレーションのための画像のムードボードを提供したり、Claude にフォントと色の組み合わせをブレインストーミングさせて、しっくりくるまでやり取りを重ねたりすることで、これを防ぎましょう。
3. **繰り返し行う作業をデザインシステムに変える。** ロゴ、スライドデッキ、スクリーンショット、タイポグラフィの仕様など、繰り返し使うブランドファイルやアセットをアップロードすれば、Claude がそれらを分析して[デザインシステムを生成します](https://support.claude.com/en/articles/14604397-set-up-your-design-system-in-claude-design)。こうすることで、その後に作る各アーティファクトが白紙の状態ではなく、あなたの選択から始まるようになります。
4. **10 個の選択肢を求め、それからリミックスする。** そのほとんどは良くないでしょうが、それでいいのです。1 つか 2 つは良いはずです。そうしたら「選択肢 B が気に入っていて、D の一部も好きです。それらを組み合わせたリフを 5 つください」と言いましょう。
5. **言葉にできないものはスケッチする。** 頭の中にレイアウトがあるのに言葉が見つからない場合は、紙に描いて写真をアップロードしましょう。
6. **指差して話す。** どの要素を指しているかを説明する段落を書く代わりに、その要素をクリックして話しましょう。デバイスでディクテーションを有効にした上で、「コメント」を選択してコメントボックスをクリックします。あなたの言葉が、タイピングしているかのようにコメントボックスに表示されます。
7. **忠実度が重要でないときはまずワイヤーフレームで。** ワイヤーフレームを頼むほうがずっと速く、Claude をビジュアルではなくデザインのより高いレベルの構造に集中させ続けられます。多くの異なるアイデアを素早く試すのに最適な方法です。
8. **最後の仕上げは手作業で行う。** 最後の仕上げには、プロンプトで頼む代わりに直接編集ツール(並べ替え、削除、テキスト編集、リサイズ、色の変更)を使いましょう。直接編集はトークンを消費しませんし、サイズや配置のような細かな調整はどのみち目で見て決めるほうがうまくいきます。
9. **Claude にあなたの実際のコンテキストを与える。** 既存のアプリやウェブサイトの機能をデザインしているなら、GitHub を接続しましょう。Claude はあなたのコンポーネントや既存の画面を取得し、それを出発点として使います。数回試すだけで、かなり高い忠実度で既存のデザインを再現できます。Web 検索と MCP 接続も Claude Design で使えるので、デザインが外部の情報に依存する場合はいつでも活用できます。
10. **Claude と一緒に作業し続ける。** Claude が結果を完成させるのを待ってから新しい変更やタスクをプロンプトする必要はありません。複数のメッセージをまとめてキューに入れることも、Claude が前のターンをまだ処理している間に話し続けることもできます。

## **生き生きとしたものにする**

デザイナーなら誰しもいつか見ておくべき、Bret Victor の講演があります。[Stop Drawing Dead Fish](https://vimeo.com/64895205) というタイトルです。その紹介文からの引用です。「私たちが描くものはすべて、デフォルトで生きているべきだ。」

Claude Design であれ他のどんなツールであれ、デザイナーには自分の作るものをどう生き生きとさせるかを考えてほしいと思います。私のお気に入りの Claude Design の作品は、既存の枠にはまらないものです。インタラクティブなシミュレーションを備えたドキュメント、あなたに語りかけてくるスライドデッキ、動画でもある図、それ自体がエディタでもあるデザイン。コード、特に HTML は創造性のための素晴らしいメディアであり、ようやくデザイナーがそれを使って創作することがある程度容易になりました。

Claude Design が今の形になったのは、Anthropic の社内の人々が私が想定していなかった使い方を次々と見つけてくれたからです。現在は Claude の Pro、Max、Team、Enterprise の各プランでベータ版として利用できます。[試してみて](https://claude.com/product/design)、私たちがまだ思いついていない場所へそれを連れて行ってください。
