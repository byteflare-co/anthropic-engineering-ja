# エージェント基盤の進化: Claude Managed Agents で構築する

エージェントを本番投入するには、優れたプロンプト以上のものが必要です。エージェントが自ら書いたコードを実行する場所、データへ到達するための認証情報、観測可能なセッション、そして利用量に合わせてスケールするインフラが必要になります。Applied AI チームでは、プロダクト・リサーチ・Claude 上で構築するカスタマーの交差点で働いており、同じパターンを何度も目にしてきました。それは、プロトタイプと本番エージェントを分けるのは結局のところインフラだということです。あまりにも多くのチームが、セキュリティ・状態管理・パーミッショニング・ハーネスのチューニングに開発サイクルを溶かしています。

[Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/overview) は、本番グレードのエージェントを構築・デプロイするためのコンポーザブルな API スイートで、パフォーマンスに合わせてチューニングされたエージェントハーネスと本番インフラを組み合わせ、プロトタイプから立ち上げまでを数か月ではなく数日でこなせるようにします。本記事では、Anthropic のエージェント構成要素の進化、Claude Managed Agents を作った理由、そしてチームが今日どのように本番で使っているのかを紹介します。

## **エージェントアーキテクチャの進化**

2023 年に Claude をデベロッパー向けに開放したとき、API は意図的にシンプルでした。トークンを入れて、トークンを返す。プロンプトを送ると Claude が補完を返し、ハーネスと足回りのインフラはあなたが組み立てる、というものです。

API はその後年々豊かになっていきましたが、その下にある契約は変わりませんでした。1 リクエスト、1 ターンのモデル呼び出し、次に何が起こるかはあなたのアプリケーションが決める、という形です。長らくはそれで十分でした。ドキュメントを要約する、サポートチケットを分類する、テキストブロックを書き直す。1 ターンに収まる種類の仕事です。

しかし時間が経つにつれ、人々が任せたい仕事はその枠に収まらなくなっていきました。Claude にタスクを最後までやり遂げてもらい、何かを調べ、それに基づいて行動し、変化を見て、次に何をするかを決めてほしい、と思うようになったのです。しかも、コードベース・社内 Wiki・チケットシステムなど、業務がすでに動いているシステムの *中で* 動いてほしい、と。

API で Claude をエージェントに変えるには、自分でループを組む必要がありました。モデルに何をするかを尋ね、ツールを実行し、その結果を返し、これを繰り返す。エージェントの足場を作ってデプロイするのもあなたの責任で、モデルの進化に合わせてチューニングが必要になることもあります。完全なカスタマイズが必要なエージェントにはこのアプローチで構いません。しかし、より予測可能で複雑性の低いエージェント型ワークロードにおいては、モデルやプロダクトが進化するたびにハーネスを最適化するのは煩雑になっていきました。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a298c28f950480f89a8dfcf_01%20_%20Messages%20API.png)

2025 年にリリースした [Claude Code](https://code.claude.com/docs/en/overview) は、Claude にコードベースを直接操作させるエージェント型コーディングツールで、私たち自身のハーネスを内蔵していました。ループ、ツール実行、サブエージェント、コンテキスト管理、そしてエージェントを実用的にする豊かな機能群です。デベロッパーが自分のエージェント向けに、さまざまな領域で同じようなハーネスの仕組みを欲しがるのは自然な流れでした。

チームが Claude Code のハーネスの上に自分のエージェントを構築できるようにするため、私たちは [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) をリリースしました。Claude Agent SDK は、自家製のループをメンテナンスする代わりに、Claude Code を動かしているのと同じ仕組みの上でデベロッパーが自分のエージェントを作れるようにします。多くのチームにとって、エージェントが実用的になったのはこの時点でした。ハーネスは Claude 向けにチューニング済みで届き、インフラのプリミティブが揃っており、Claude Code とともに改善され続けるからです。

ハーネスがあっても、本番環境にエージェントをデプロイするのはいくつかの理由で難しいままでした。

- **ホスティングとスケーリング。** エージェントはどこで動くのか、数時間に及ぶタスクのためにプロセスはどれだけ長く生き続けられるのか、利用量が増えたときに何がスケールさせるのか。
- **セッション管理。** エージェントの履歴と進行状況はどこに置かれるのか。中断を生き延びて、引きずらずに再開できるのか。過去のセッションに遡って何が起きたかを検査できるのか。
- **ファイルシステム管理。** 実際の仕事をするということは、成果物を生み出すことです。コードを編集し、ファイルを書き、出力物を組み立てる。エージェントが作業するワークスペースはどこから供給され、実行と実行の間でそのワークスペースはどうなるのか。
- **実行の分離。** Claude が書いたコードはどこかで実行されなければなりません。そのコードが間違っていた場合の影響範囲はどこまでで、本番で本当に信頼できる境界はどこに引くのか。
- **認証情報。** エージェントはあなたのシステムへのアクセス権が必要です。それを、生成されるコードに専有情報を晒すことなくどう渡すのか。
- **観測可能性。** エージェントが 1 時間自律的に動いて何か驚くようなことをしたとき、その全ステップを再構築できるのか。

Agent SDK では、これら本番インフラの多くの要素が Claude Code の仕組みを通じて提供されます。エージェントは作業のための実ファイルシステムを得て、セッション状態はローカルまたは外部ストレージに永続化され、観測可能性は OpenTelemetry 経由で既存のモニタリングスタックにエクスポートできます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a298c53aaeeee508f2b3166_02%20_%20Claude%20Agent%20SDK.png)

ただし、ローカル開発から本番に出ていくエージェントをチームが作るようになるにつれて、それらをスケールさせ、マネージドなインフラでデプロイする手段が必要になってきました。また、モデルとその周辺ハーネスが高度化し、より長く走り、より多くのコードを実行し、より多くのシステムに触れ、より多くのアクションを取るようになるにつれて、スケーリング・セキュリティ・サンドボックスはより難しくなっていきました。

これらのハードルのいくつかは、共通のアーキテクチャ上の選択に起因しています。エージェントハーネスは、しばしば作業対象のファイルシステムと *同じコンテナの中で* 動いているのです。Claude が考え始める前にコンテナが立ち上がる必要があり（その起動コストを払うことになります）、エージェントとコード実行はあなたの認証情報のすぐ隣に住み、コンテナが死ねば実行も一緒に死にます。

Managed Agents は、[頭脳と手を切り離す](https://www.anthropic.com/engineering/managed-agents) ことでこれらの問題を解きます。Claude を呼ぶハーネスは、コードを実行するサンドボックスとは別に動き、その 2 つをつなぐのが *セッション* です。セッションとはすべてのモデル呼び出し・ツール呼び出し・結果を追記専用に並べたログです。Claude はコンテナがまだ存在しないうちから推論を始められ、サンドボックスはあなたの認証情報から十分に遠くに留まり、実行全体はそのセッションからいつでも再構築できます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a298c97d4a887f2666a50b6_03%20_%20Claude%20Managed%20Agents.png)

## **Claude Managed Agents をいつ・なぜ使うのか**

Managed Agents で構築するとき、ユーザーはタスク・ツール・ガードレールを定義し、Anthropic がそのエージェントを自社のインフラ上で動かし、足回りのエージェントループ（エージェントにツール呼び出しのための実行環境をどう与えるか、何かが失敗したときにどう回復するか、マルチエージェントオーケストレーションなど）を引き受けます。

ハーネスがモデルの知能と一緒に進化しないと、[エージェントは壊れていきます](https://www.anthropic.com/engineering/harness-design-long-running-apps)。Claude Sonnet 4.5 では、エージェントがコンテキストの終わりに近づくと、残っている余地を使うのではなく仕事を切り上げて急いで終わらせようとする挙動がありました。「コンテキスト不安（context anxiety）」と呼ばれるパターンです。私たちの対処は、コンテキストリセットをハーネスに加えることで、Claude が上限付近で一貫性を保つには助けが要るという前提を組み込みました。その前提は次のモデルでは生き残りませんでした。Claude Opus 4.5 ではこの挙動は消え、追加したリセットはただのオーバーヘッドになっていました。

ほとんどの組織にとって、ハーネスを保守することは、プロダクトを差別化しないオーバーヘッドです。ハーネスは特定のモデル挙動に合わせてチューニングする必要があり、コンパクション・ツール実行・キャッシングといったプリミティブは、Claude と他モデルでは挙動が異なります。Claude Managed Agents では、ハーネスはモデルと一緒に進化するため、チームは自社のエージェントを差別化する **コンテキスト管理とドメインの専門知識** に集中できます。

デベロッパーが有効なエージェントを構築するために必要なコンテキストとツールを構成できるよう、Managed Agents は 3 つの主要リソース、agents・environments・sessions を中心に設計されています。*agent* は構成です。モデル、プロンプト、ツールのセット、そしてそれらに対するガードレールです。*environment* はエージェントが動く実行コンテキストで、サンドボックスコンテナ、そのネットワークルール、プリインストールされたパッケージから成り、当社のクラウドまたはお客様が管理するインフラ上でホストされます。各実行は *session* で、agent と environment を組み合わせ、独立したサンドボックスインスタンスを得ます。セッションは完全なイベント履歴・サンドボックス状態・出力をサーバー側で永続化するため、長時間の仕事を一時停止し、きれいに再開し、後からステップごとに追跡できます。Managed Agents では、agent と environment を一度定義すれば、ワークロードが拡大しても同じ構成に対して多数のセッションを走らせられます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a29a18bb07e245f8389acb9_04%20_%20Agents_%20environments_%20sessions%20(2).png)

## **Managed Agents で本番とスケールに向けて構築する**

Applied AI では、Anthropic 社内とお客様のシステム横断で、コーディング・金融・サポート・法務その他のドメインにわたってエージェントがプロトタイプから本番へ移っていく様子を見ています。これにより、デモと本番対応のエージェントを分けるものが何か、そしてチームがどこで詰まりがちかが鮮明に見えてきます。

以下では、Claude Managed Agents のようなマネージドサービスの上に構築する代表的な理由を共有します。

**1. 認証情報をサンドボックスの外に保つ。** すべてが 1 つのコンテナで動いていると、Claude が生成するコードはあなたの認証情報のすぐ隣に置かれることになります。そのため、プロンプトインジェクションによってモデルに自分の環境を読ませ、トークンを漏らさせることが起こりえます。同じコンテナ内に頑健なガードレールを敷くことで一定の防御はできますが、アーキテクチャを分離すれば、認証情報をサンドボックスから完全に追い出すというずっと安全なアプローチが可能になります。MCP・CLI・GitHub リポジトリといったツール向けのトークンは別の vault に住み、プロキシがオンデマンドでのみ取得・復号します。Managed Agents は [Vaults](https://platform.claude.com/docs/en/managed-agents/vaults) を提供し、認証情報を標準で処理します。自前のシークレットストアを動かしたり、呼び出しのたびにトークンを送信したり、どのエンドユーザーの代理でエージェントが動作したのかを見失ったりする必要はありません。vault の認証情報は保存前にエンベロープ暗号化で保護され、取得には検証用に署名済みのリクエストトークンが必要です。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a29a19cebb4eb7adac0a8ec_05%20_%20Managed%20Agents%20runtime%20(1).png)

**2. サンドボックスのオーバーヘッドを排除した低レイテンシ。** レイテンシは多くのエンタープライズチームにとって最重要級の指標です。ユーザーは Claude の応答を待たされていることを敏感に感じ取るからです。Managed Agents のアーキテクチャがなければ、エージェントが思考するだけでツールを 1 度も使わないようなセッションでも、毎回コンテナを立ち上げる必要があります。その立ち上げ時間は無駄になり、ユーザーには最初の応答までの遅延として感じられます。Managed Agents では、Claude はすぐに推論を始め、その裏で environment が並列に立ち上がります。ツールを 1 度も使わないセッションはコンテナを完全にスキップします。これにより、ユーザーはコンテナ起動を待たずに最初のトークンを目にし、エージェントが何かを実行する必要が出たときには environment が用意できています。私たちのテストでは、Time-to-First-Token をメディアン（p50）でおよそ 60%、最も遅いケース（p95）で 90% 以上短縮できました。

**3. 信頼性と永続性のあるセッションが、セッション管理・観測可能性・メモリを支える。** Managed Agents はリクエスト/レスポンスではなく、*イベント* で考えます。セッションはイベントの継続的なストリームです。すべてのモデル呼び出し、ツール呼び出し、結果が、エージェントを動かしているプロセスの外側に存在するログに追記されていきます。このアーキテクチャによって、エージェントが働いている間にイベントがストリーミングされるリアルタイム更新を得られ、データベースやセーブポイントを管理することなく任意のセッションを後から再開できます。セッションを削除しない限りインタラクションの間で履歴は保たれ、セッションがアイドルになるとそのコンテナはチェックポイントされるため、停止した場所からきれいに再開できます。そして、実行全体がすでにイベントの記録になっているため、観測可能性とメモリも自然に付いてきます。Claude Developer Console はエージェントセッションのネイティブなビジュアルタイムラインビューと、任意のトランスクリプトを詳細に検査できるデバッギング体験を提供します。Managed Agents には、このセッションの永続性を活用する Memory や Dreaming などの機能もあります。[Dreaming](https://platform.claude.com/docs/en/managed-agents/dreams) はスケジュールされたプロセスで、エージェントのセッションとメモリストアをレビューし、パターンを抽出し、メモリをキュレートして、エージェントが時間と共に改善されるようにします。Dreaming は永続化されたセッションログを読み取って、繰り返し起こるミスやユーザーの嗜好からセッション間でメモリを洗練し続けます。

**4. Anthropic マネージドのクラウドコンテナまたはセルフホストのコンテナを柔軟に選べる。** Managed Agents ではデフォルトで、オーケストレーションとツール実行の両方を Anthropic マネージドのクラウドコンテナに委任できます。これによりホスティングとスケーリングはシンプルになり、本番までの道のりが早まります。Managed Agents では頭脳と手が切り離されているため、手はあなたの仮想プライベートクラウド（VPC）の中も含め、どこにでも置けます。そこで、ツール実行をコントロールしたいチームのために [セルフホストのサンドボックス](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes) も提供しています。エージェントのコード・ファイルシステム・ネットワーク egress は彼らの環境から一切出ません。また、Claude をお客様のプライベートネットワーク内で動く Model Context Protocol (MCP) サーバーに接続できる [MCP tunnels](https://platform.claude.com/docs/en/agents-and-tools/mcp-tunnels/overview) も提供しています。つまり、セルフホストのサンドボックスは *エージェントのコードがどこで実行されるか* を、MCP tunnels は *Anthropic がお客様のネットワーク内の MCP サーバーへどうやって到達するか* をコントロールするものであり、両者を組み合わせることで、何を自分の境界の内側に留めておくかを正確に制御できます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a298e427c7a804ea4295163_image7.png)

*Claude Managed Agents の組み込み観測可能性コンソールはすべてのイベントを記録するため、タイムラインをスクラブし、任意のステップを開いて生のペイロードを読むことができます。*

これらの機能に加えて、エージェントがルーブリックに照らして自分の仕事を採点する outcomes、マルチエージェントオーケストレーション、permission policies、webhooks といった追加機能もあります。詳細は [こちら](https://platform.claude.com/docs/en/managed-agents/overview) をご覧ください。

### **カスタマーが今日 Managed Agents で何を構築しているか**

業界を横断して、お客様はすでに Claude Managed Agents で本番エージェントを出荷しています。いくつか例を挙げます。

- [Notion](https://claude.com/customers/notion) は自社の Custom Agents を Managed Agents の上で動かしています。チームはタスクボードから直接 Claude に仕事を割り当て、Claude は各タスクの周辺にあるドキュメント・会議メモ・接続されたデータを拾い上げ、完成したコード・スライド・サイトをレビューのためにワークスペースへ返します。数十のタスクが並列に走り、初期プロトタイプではおよそ 12 時間の仕事を 20 分にまで短縮できたとチームは語っています。
- [Rakuten](https://claude.com/customers/rakuten) は Managed Agents を使って、プロダクト・セールス・マーケティング・ファイナンスを横断してスペシャリストエージェントを出荷し、それぞれおよそ 1 週間でローンチしました。
- [Sentry](https://claude.com/customers/sentry) は自社の Seer デバッギングエージェントを、パッチを書いて PR を開く Claude エージェントと組み合わせ、エンジニア 1 人で数か月ではなく数週間で構築しました。
- [Asana](https://claude.com/blog/claude-managed-agents) はプロジェクト内でタスクを引き取る AI Teammates を構築し、[Atlassian](https://claude.com/blog/claude-managed-agents) はデベロッパーエージェントを Jira のワークフローに組み込みました。

## **Claude Managed Agents を始める**

私たちは Managed Agents を、Claude Code と Claude Developer Console（[platform.claude.com](http://platform.claude.com)）を通じてできるだけ簡単にエージェントを立ち上げられるように作りました。たとえば Console のクイックスタートでは、エージェントのテンプレートから始めるか、エージェントを自然言語で記述してから、それを数分でセキュアにデプロイ可能な本番グレードのエージェントへ変えられます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a298e9b866a4402a3c9bb5d_image5.png)

*platform.claude.com のエージェントクイックスタート: テンプレートから始めるか、作りたいものを言葉で記述する。*

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a298ebdff6d26839e052c63_image9.png)

*数ステップ進んだ後の様子: エージェントが作成され、environment が構成され、session がライブで動いている。コンソールが実行をリアルタイムでストリーミングする。*

Claude Code では [/claude-api skill](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/claude-api-skill) がデフォルトで提供されており、Claude Managed Agents 上でアプリケーションを構築するための詳細で最新のリファレンス情報を Claude に渡します。Managed Agents アプリケーションをセットアップするベストプラクティスのために、ぜひ活用することをお勧めします。`/claude-api managed-agents-onboard` を実行すると、新しい Managed Agent をゼロから立ち上げるためのインタビュー形式のウォークスルーが始まります。
