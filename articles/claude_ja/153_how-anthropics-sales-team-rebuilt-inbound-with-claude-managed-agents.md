# Anthropic のセールスチームが Claude Managed Agents でインバウンドを作り直した方法
- 著者

  Carl Johnson

セールスリーダーとして認めるのは心苦しいのですが、少し前まで、自社のために Claude を購入したいと考えている人たちは、必要な答えを十分な速さで得られていませんでした。彼らは Contact Sales フォームに記入しても、返信を受け取るまでに長く待たされ、時には数日かかることもありました。彼らの質問のほとんどはシンプルなものでした。プランの価格はいくらか、シート数の最低条件はあるか、HIPAA の契約要件を満たせるか、といったことです。答えはドキュメントやサポート記事に載っていましたが、顧客はそれを誰かに素早く案内してもらいたいと考えていました。

そこで私たちは、Claude Managed Agents(ベータ版)上に購買エージェントを構築しました。これは、見込み客の「自社のために Claude が欲しい」という気持ちから、購入完了までを担うものです。この購買エージェントは現在、1 日に数千件の会話を行い、顧客の最も差し迫った質問に答え、チェックアウトまで案内しています。このエージェントが私たちのチームにエスカレーションする顧客は、すでに十分な知識を持ち、購入の意思決定によりよく備えた状態でやって来ます。以前のフォームから来るリードと比べて、案件化する割合は 2 倍以上になり、成約までの期間も約 5 日短縮されました。このエクスペリエンスは意図的にオプトインにしており、顧客は最初の段階で、エージェントと話すか営業担当者と話すかを自分の好みに応じて選べるようになっています。

## **旧来のインバウンドプロセスが破綻した理由**

購買エージェントを構築する前、私たちのインバウンドプロセスはかなりシンプルなものでした。買い手がフォームに記入します。そのリードは営業開発担当者(BDR)にルーティングされ、そこで見込みを判定した上でアカウントエグゼクティブに引き継がれます。この仕組みは、関心を持ったすべての顧客とチームが会話できる限りは、うまく機能します。

しかし私たちは毎月数万件ものインバウンドリクエストを受けており、インバウンド BDR チームはそれに追いつけなくなっていました。担当者たちは、ドキュメントにすでに書かれている質問に答えることに一日を費やしており、キューに溜まったすべての顧客に効果的にアプローチする手段を持っていませんでした。これは、私たちが顧客に提供したいと考えていた体験ではありませんでした。

私たちは、どの顧客にも、いつでも、どの言語でも、知識に基づいた答えが得られるようにしたいと考えていました。そして、好みに応じて――多くの場合は営業担当者と話すことなく――購入できるようにしたいと考えていました。また、担当者たちには、会話の行方を大きく変えられるような場面にこそ時間を使ってほしいと考えていました。

## **ギャップを埋める購買エージェント**

私たちはこのエージェントを、顧客がすでに質問をしている場所――[Contact Sales](https://claude.com/contact-sales) ページと [Pricing](https://claude.com/pricing#team-&-enterprise) ページ、プロダクト内、そしてメールの中――に展開しました。どの顧客も [Claude.ai](http://claude.ai/redirect/claudedotcom.v1.267196b9-dc38-4460-b459-95b5d8efbfbe) プロダクト内で購買エージェントを見つけることができ、それはシンプルなチャット体験として、顧客がどのプランが最適かを理解する手助けをします。顧客がチームに必要なことを説明すると、エージェントはいくつかの追加質問をし、その後、価格、セキュリティ、データに関する質問に答えてから、プランとシート数を推奨します。それぞれの会話は、次の 3 つのいずれかの形で終わります。

- **購入。** 買い手はそのままチェックアウトに進みます。
- **引き継ぎ。** より大規模、あるいはより複雑な案件の場合、エージェントは会話の詳細一式とともに買い手を担当者に引き渡します。
- **簡単な回答。** 顧客が必要としているのはそれだけ、という場合もあります。

私たちはこのエージェントを、営業担当者と同じ仕事の流れをたどるように構築しました。つまり、顧客が解決しようとしていることは何か、現在の Claude の利用状況はどうなっているか、そして私たちがどう最も力になれるかを理解するということです。

## **なぜ Claude Managed Agents を使ったのか**

内部的には、購買エージェントはシンプルです。プロンプトと、いくつかのツールと、Claude Managed Agents 上で動く Claude だけです。ホスティング、セッション管理、ツールのオーケストレーションはプラットフォームが面倒を見てくれるため、私たちのエンジニアはインフラを構築する代わりに、セールスチームと一緒に購買体験をデザインすることに時間を使えました。

私たちが最終的に Managed Agents を選んだ理由は、次の通りです。

- **本番投入までが速い。** エンジニア 1 人が、わずか数週間で Managed Agents 上に最初の購買エージェントを構築しました。
- **技術系・非技術系双方の貢献者が関われる。** コードはエンジニアリングが所有しましたが、システムプロンプトそのものはセールスやコンテンツのリードが Console 上で直接レビューし、編集しました。変更はまずステージング用エージェントに反映されるため、誰でも顧客に届く前に修正を試すことができました。
- **ハーネスではなくドメインに集中できる。** Managed Agents がエージェントループ、セッション、ホスティングを担ってくれます。私たちは、販売に固有の 3 つの要素――プロンプト、ツール、ナレッジベース――に時間を使いました。
- **バージョニングによって反復のコストが下がる。** エージェントへの変更はすべて、それぞれ独立したバージョンとして保存されます。社内テストを始めて 1 週間ほどでバージョン 7 に達しており、ローンチ後もプロンプトの変更を毎週出し続けました。必要があれば、新しいセッションを簡単に以前のバージョンに戻すこともできました。
- **より多くのユースケースに対応する柔軟性。** 現在、顧客はウェブサイト上でこのエージェントを見つけますが、Managed Agents はスケジュール実行にも対応しているため、他の種類の顧客エンゲージメントを探る道も開かれています。

## **購買エージェントを構築して学んだこと**

**ルールではなくゴールを Claude に与える。** エージェントのゴールを説明する方が、詳細な指示のリストを与えるよりもうまく機能しました。たとえば、「あなたのゴールは、顧客の要件を理解し、見込み客を評価し、最適なプランを推奨することです」というシンプルな一文の方が、フローチャート上にすべての評価要件を列挙するよりも効果的でした。

**Less is more。** 私たちは長さ、複雑さ、構造の異なるさまざまなプロンプトを試し、「少ないほど良い」という格言が最もうまく機能することを見出しました。今日のモデルは、複雑で微妙なニュアンスを持つゴールを理解し、そこから逆算して動くことができます。実際には、これはシート課金制の対象範囲や請求サイクルの起算日といった、成功のために必要な知識とコンテキストを与えることで、Claude の邪魔をしないようにすることを意味していました。

**開発ループに主題専門家(SME)を関わらせる。** エージェントによるコーディングが開発サイクルを高速化させている世界において、これはますます価値を増しています。Managed Agents と Claude Code を使って時間を節約できたおかげで、私たちのエンジニアはセールスチームとより多くの時間を過ごし、顧客中心の体験を形作ることができました。私たちは早い段階から頻繁にエージェントをテストでき、それが素早い反復につながりました。

**顧客にとって正しいことに焦点を当てる。** このエージェントは、場合によっては小規模なチームを Enterprise ではなく Team プランに案内することがよくあります。それが正しい答えだからです。私たちは、それを一つの機能として位置づけることにしました。アップセルされるのではなく正しいプランにたどり着いた買い手の方が、長く使い続け、より良い体験を得やすいのです。

**エージェントから担当者へのエスカレーションはすべてフィードバックとして扱う。** エージェントが買い手を担当者に引き渡すたびに、その理由を説明します。初期の頃、その理由の大半は、顧客がセルフサービスのプロダクトだけではまだ自力で対応できないことに関するものでした。こうした理由が、体験をどう改善するかの指針となり、成約に人の手が必要になる会話の割合は約半分に減少しました。

## **顧客にとって何が変わったか**

このエージェントは現在、24 時間体制で 1 日に数千件の会話を行っています。顧客は、予定された通話を待ったり、数日かけてメールをやり取りしたりする代わりに、その場で質問への答えを得られます。実際、多くの顧客は、人間よりもエージェントと話す方を好みます。疑問が生まれたそばから、素早く十分な情報に基づいた答えを得られるからです。新たにセルフサービスで契約する Enterprise 顧客の多くは、購入前に購買エージェントと会話しており、事前にエージェントと話した顧客の方が、自分が何を購入しようとしているのかをよく理解していることがわかっています。

## **エージェントがセールス組織にもたらした変化**

このエージェントは、私たちの担当者が日々の時間をどう使うかを変えました。今では、チームの時間とエネルギーの大部分を、購買の旅の早い段階で顧客を教育すること、より多くの顧客とライブで会話すること、そしてイベントで対面の時間を過ごすことに充てられるようになっています。

最も大きな影響は、担当者たちがより十分な情報を持ったリードを得られるようになり、旧来の Contact Sales フォームよりも高い頻度でリードを案件に転換でき、成約までの期間も約 5 日短縮されたことです。担当者は、顧客が何を必要としているか、これまで何を案内されてきたか、そして私たちがどう最も力になれるかをすでに知った状態で会話を始められます。

たとえば、インサイドセールス担当者の一人である Ojas は、以前は 1 件の成約のために約 10 通のメールをやり取りしていましたが、今では約 6 通で済んでいます。購買エージェントのローンチ以降、成約案件でのアウトプットを 2.5 倍に伸ばすことができました。すでに十分な知識を持ち、あと一押しで成約に至る準備が整った顧客に集中できるようになったためです。

少し前まで、インバウンドは私たちのチームが追いつけないキューでした。今では、どんな買い手でもいつでも始められる会話になり、私たちの担当者はより効率的に時間を使えるようになりました。購買エージェントは、顧客関係全体にエージェントを広げていくための、私たちにとっての最初の一歩です。
