# Anthropic のマーケティングオペレーションチームは Claude Cowork でレポート作成とキャンペーン構築をどう自動化しているか

マーケティングオペレーションチームは、マーケティング施策の裏側で動く各種システムを事業の動きに追従させることに、業務時間のかなりの部分を費やしています。自動化はまさに彼らの守備範囲ですが、実際の作業の多くはとても自動化されているとは言えません。マーテック系のツール同士はきれいに統合されておらず、レポートは手作業でつなぎ合わされ、ランディングページは 1 つずつ立ち上げられていくのが実情です。

Anthropic のマーケティングオペレーションチームに所属する Ian Chan は、これまで週に 1〜2 日を、週次のマーケティング指標レビューの取りまとめに費やしていました。キャンペーンオペレーションを担当する Annabel Custer は、新しいイベントを立ち上げるたびに、Salesforce、HubSpot、Swoogo、メールツールを順にクリックして回っていました。今では 2 人とも、Claude Cowork にワークフローを組むことで、数日分の手作業を数時間にまで圧縮しています。

こうして取り戻した時間は、彼らの仕事の中身そのものを変えつつあります。Ian と Annabel は今、システムを渡り歩くクリック作業に費やす時間を減らし、代わりにイネーブルメントや検証、そしてマーケティングチームが依拠しているデータや業務プロセスの土台部分により多くの時間を割いています。社内の各所でより多くの人が自ら数字を取りに行き、自分たちの施策を回し始めていることを踏まえての変化です。

## **週次マーケティング指標レポートの生成**

理想的な世界であれば、Ian がマーケティングとリーダーシップ向けに用意する週次レポートに載る指標はすべてダッシュボードに揃っていて、彼の仕事はそこにナラティブを添えるだけで済むはずです。ところが現実には、すでにダッシュボードに載っている指標もあれば、データウェアハウスからまだダッシュボードに反映されていない指標もあり、そもそもウェアハウスに流れ込んでいない指標さえあります。新しい指標が Slack のメッセージや会議の書き起こしにしか存在しない、ということも起こります。

Anthropic ではビジネスの動きが、従来型のレポーティングパイプラインが追いつけないほど速く、Ian は毎週 1〜2 日をデータの追跡と検証に費やしていました。今ではその「データ狩り」のほとんどを Claude Cowork が引き受けています。

日曜の夜には、あらかじめスケジュールしておいたタスクが実行されます。Claude は前週のレビューと直近のミーティング書き起こしを読み、営業チームがいま何に注力しているかを Slack で確認し、ウェアハウスにクエリを投げ、数字と注目すべきポイントの候補をまとめたフォルダを残します。

月曜の朝、Ian は Claude Cowork を開き、指標テーブルと注目トピック (ヘッドライン) の候補を含む初回レポートを取り出します。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a4c4a528dff4302c054e6cd_47666869.png)

*ここに示す週次ビジネスレビューのサマリは、公開用にデモデータで作成し、あらゆる情報を匿名化・改変したものです。*

Ian はそれらに目を通し、ナラティブの焦点をどこに置くかを確認あるいは決定したうえで、Claude に対して裏付けとなる詳細や事例を交えて内容を展開させます。ある週は営業側の優先事項に対応する形になり、別の週はプロダクトのローンチが軸になります。四半期の切り替わりのタイミングでは、Ian は Claude に対して四半期プランを冒頭に据えるよう指示し、四半期レビューのドキュメントを読み込ませます。

Claude は同じデータとナラティブから、リーダーシップ向けのスライドも生成します。何が変わったか、なぜ変わったか、そして各チームがそれに対して何をしようとしているのか、といった内容です。フォローアップ事項は Asana タスクになります。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a4c4a528dff4302c054e6d0_9a64f8ed.png)

*ここに示す週次指標レポートは、デモデータで作成し、あらゆる情報を匿名化・改変したものです。主要指標と、注目すべきポイントの候補が含まれています。*

数字が合わないときには、Claude は当て推量で処理するのではなく、その食い違いにフラグを立てます。たとえば営業チームの組織改編が入ったあと、マーケティング側のレポートが営業側のそれと合わなくなったことがありました。このとき Claude はギャップを検出し、どう扱うべきかを Ian に尋ねました。

このプロセスは、チームが使っているマーケティングプラットフォームやツールへのコネクタと、Ian が自ら作り、継続的に更新している 3 つの skill の上で動いています。

- **prep skill** が、フォーカスの選定、ヘッドライン、そして裏付けを伴った内容の展開まで、レポート組み立て全体を駆動します。
- **proofreading skill** が、下書きに含まれるすべての数字を検証済みのソースと突き合わせてチェックします。
- **action-items skill** が、フォローアップ事項を Asana タスクへと変換します。

毎週のセッションの最後には、Ian は Claude に対して「今週出てきたトピックのうち、skill に反映しておくべきものをまとめて」と指示します。たとえば新しい営業組織の構造や、その週にした修正、あるいはヘッドラインの表現をどう変えたいと思ったか、といった内容です。Ian の場合、以前は最大 2 日かかっていたこのプロセス全体が、今では最大でも 2 時間で完了します。

いま、Ian の時間の相当部分は、マーケターが問いを立て、プロンプトを磨き、Claude から返ってきた結果を解釈するのを支援することに移っています。マーケター自身が Claude から数字を引き出せるようになるためです。さらに、データ層に踏み込む余裕もでき、Claude が数字、定義、地域構造をデータウェアハウスと同じ意味で解釈しているかを確認できるようになっています。

人による検証は、両方のワークストリームにおいて不可欠な要素となりつつあります。マーケティングアナリストの時間の多くを従来奪ってきた、地道な手作業を Claude が自動化していくにつれ、この動きは加速しています。

## **イベント構築とデータインポートの自動化**

マーケティングキャンペーンの裏側にあるインフラの設定は、従来、マーケティング業務のなかでも最も手作業の多いプロセスの 1 つでした。イベント、ウェビナー、統合キャンペーンのいずれについても、CRM に設定し、メール配信シーケンスとその裏側の自動化を動かすマーケティングオートメーションプラットフォームに設定し、登録ページとイベント用ランディングページをホストするイベント管理プラットフォームに設定する必要があります。これらはたいてい別々のベンダーで、相互の連携も完璧とは言えません。

Claude Cowork を使う前、Annabel は専用の Slack チャネルに来る依頼を 1 件ずつ拾い、シーケンスを手作業で進めていました。新しいセットアップでは、その大部分を Claude が引き受けています。依頼者が必要な支援の種類——イベント構築、データインポート、参加申請 (apply-to-attend)、承認サポートのいずれか——を指定する受付フォームから始まります。

1 時間ごとに、**dispatcher skill** がチャネルを読み、最も緊急度の高い依頼を選び、作業が重複しないようチケットに印を付け、Annabel が用意しておいた 5 つの specialist skill のうち、要件に合ったものへと引き渡します。dispatcher 自身はイベント設定を行いません。その役割は次に何を実行するかを決めることであり、この分離のおかげで、Annabel はルーティングに手を入れずに各 specialist skill を個別に磨き込むことができます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a4c4a528dff4302c054e6d3_36d62936.png)

*公開用にデモデータで示した dispatcher skill。チャネルを読み、依頼を、必要な作業を担当する 5 つの specialist skill のいずれかに引き渡します。*

最も複雑な依頼タイプであるイベント構築については、**event-build skill** が全工程を一気通貫で処理します。CRM 上のキャンペーン作成、ワークフローとリスト付きのマーケティングオートメーションキャンペーン、イベントプラットフォームのセットアップ、メールの下書き、ランディングページ生成、そしてそれらを結ぶすべての連携までを含みます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a4c4a528dff4302c054e6d8_be52735c.png)

*event-build skill (公開用に抜粋・編集済み) は、2 つの Slack 更新を発するようスクリプトされています。Claude が依頼を受け取ったとき、そしてランディングページが依頼者のレビュー可能な状態になり、監査 (audit) に引き渡されるときです。*

構築が終わると、監査のために新しいエージェントに引き渡されます。**audit エージェント**は事前のコンテキストを持たない状態からスタートし、公開されたランディングページ上で実際にテスト用の登録を送信し、Gmail で確認メールを開き、すべてが正しければ Asana タスクを完了としてマークします。Annabel は納品前に個々の結果をレビューします。

このワークフローは、Annabel が業務で使っているマーケティングプラットフォームやツールへのコネクタと、彼女が構築し、新しいエッジケースを見つけるたびに更新している複数の skill の上で動いています。

- **dispatcher skill** は受付チャネルを読み、各依頼を下記の適切な specialist skill にルーティングします。
- **event-build skill** は複数のプラットフォームをまたぐ一気通貫のセットアップを駆動します。
- **webinar-landing-page 作成 skill** はウェビナー用のランディングページを立ち上げます。
- **audit skill** は別の新しい Claude インスタンスによって実行され、event-build skill の出力をタスク完了とマークする前に検証します。
- **apply-to-attend skill** は、登録フローに対する進行中の変更を扱います。
- **approval-support skill** はイベントの承認処理を担当し、スケジュールされたタイミングで適切なメールを送信します。
- **data-import skill** はリストのクレンジングと参加者データの処理を行います。

彼女はまた、別途「manager」エージェントも常時開いています。実行がうまくいかなかったときには、manager を開いて、何が起きたかを見て何を調整すべきかを提案するよう頼みます。取り込む価値のある内容は、該当する skill にフィードバックとして戻されます。

こうした自動化されたワークフローは、いずれ Annabel の日々の業務における大きな時間節約になっていくはずですが、彼女が構築に取り組んだ最大の動機は、実は仕事の品質でした。マーケティングチームが拡大していくなかで、マーケターが手近なテンプレートをコピーして作ったイベントページからは、確認メールに間違った都市名が表示されたり、ランディングページが壊れていたりといったバグが生じ得ます。Claude Cowork によって、彼女はスケールしても構築間の一貫性を確保できるようになりました。

キャンペーンオペレーションの反復的な部分を Claude が引き受けていくことで、Annabel はイネーブルメントや、より深いインサイトを得るための業務プロセスやキャンペーン構造の自動化・最適化といった、より戦略的なプロジェクトに集中できるようになっています。

## **Claude Cowork を使い始めるマーケティングオペレーションチームへのアドバイス**

- **繰り返す修正は skill にする。** 同じ点について Claude を 2 回以上修正しているのに気づいたら、そのフィードバックは skill に落とし込むべきものです。自分で作らなくても構いません。Claude に作ってもらえばよいのです。
- **まず proofreading skill を作る。** proofreading skill は、Claude がレポートに載せるすべての数字が、検証済みのソースまで辿れることをチェックします。

- **Claude に振り返らせる。** Claude は人間が書く指示を、人間とは違う読み方で解釈します。ですから、新しいワークフローを何度か回したあとに、指示のうちどこが難しかったかを尋ねてみてください。Annabel はそこで浮かび上がったものを、常に skill を更新し続けるという広い実践の一環として、skill にフィードバックしています。

- **スケジュールタスクを使い倒す。** 毎週日曜の夜や 1 時間ごとに自動で走る仕事は、誰も覚えておかなくてよい仕事になります。
