# Anthropic の社員は Claude Tag をどう使っているか
- 著者

  Aleksandra Todorova

[Claude Tag](https://www.anthropic.com/news/introducing-claude-tag) は、Slack のようなチャットツールに Claude を組み込む機能です。同僚にタグ付けするのと同じように、スレッド内で @Claude とタグ付けすると、Claude は会話の文脈を把握し、タスクを完了させ、回答や結果をそのスレッドに投稿してくれます。また、[会話を追跡し](https://claude.com/blog/claude-tag-now-reads-even-more-of-the-room)、利用可能な文脈やメモリ、与えられた常設の指示をもとに、いつチャットに参加すべきかを自ら判断することもできます。ここ数か月、Anthropic 内の各チームは Claude Tag を活用し、共有チャンネルでの[セルフサービス型のデータ分析](https://claude.com/blog/self-service-data-analytics-in-slack-how-anthropic-deploys-claude-tag-for-ad-hoc-questions)や、サポートチケットの処理、厄介なバグの[根本原因](https://www.anthropic.com/news/introducing-claude-tag)の特定などに役立ててきました。

私たちは、Anthropic での実際の業務にヒントを得た、[Claude Tag のユースケース例](https://claude.com/docs/claude-tag/users/use-cases)を具体的なプロンプトやセットアップ手順とともに12件以上まとめました。本記事では、Anthropic の社員が Claude Tag を使ってワークフローや業務プロセスをより効率化している3つの事例を、実際に使われたプロンプトとともに紹介します。自分の業務に合うものがあれば、そのまま、あるいはアレンジして活用してください。

## Slack のスレッドを整った文書に変換する

先日のある機能リリースの際、営業担当者から、その機能の仕組みを顧客や見込み客に説明する非技術者向けの資料が欲しいという依頼がありました。プロダクトマーケティングチームの Hema Thanki は、それに続く Slack スレッドを、45分でレビュー可能な状態の文書に仕上げました。

そのスレッドは15件を超えるメッセージに膨らみ、複数の人が提案や追加の要望を書き込み、本当に何が必要なのか、既存の技術資料で十分なのかをめぐって、ちょっとした緊張感も生まれていました。Hema はその曖昧さを自分で整理しようとする代わりに、スレッド内で Claude にタグ付けしました。「@Claude、このSlackスレッドに目を通して、[依頼者]が求めている1ページ資料を作成して」

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a91db2a994de3cf1ac088c6_c0ede71e.png)

*Slack スレッドをもとにマーケティング資料の生成を Claude に依頼している様子。この画像はユースケースを説明するために生成されたものであり、実際の情報は含まれていません。*

Claude は約2分で2ページの草案を作成し、その機能が何をするのかを平易な言葉で説明したうえで、ビジネス上の意義、実装に必要な内容、そしてより詳細な情報を含む付録までまとめました。

続けて Hema は Claude に自らの回答を検証するよう依頼しました。「@Claude、この文書の内容はすべて事実に基づいて正確ですか?」 Claude は文書内の主張を、公開ドキュメントで裏付けが取れたものと、自分自身の解釈によるものとに仕分け、後者についてはプロダクトリードの承認が必要だとフラグを立てました。Hema が関連情報を含む公式リソースを2件提供すると、Claude はそれらの資料の承認済みの文言に合わせて該当セクションを書き直しました。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a91db2a994de3cf1ac088c9_e46dcfe0.png)

*Claude へのフォローアップの指示も Slack 上で行われます。この画像はユースケースを説明するために生成されたものであり、実際の情報は含まれていません。*

その後 Hema は、スレッドが省略表示されていたことで内容の方向性が偏っていたことに気づき、より完全な文脈を貼り付けました。Claude とのやり取りを重ね、最終的に4つのバージョンを経て、最初の依頼から約45分後に、その機能のプロダクトリードにレビュー用として文書を共有しました。文書の調査や執筆に何時間もかける代わりに、Hema の時間は正確性の検証や情報源の提供、盛り込む内容の判断といった、人間の判断が必要な作業に使われ、結果として顧客向け資料の質もより高まりました。

Hema は Slack スレッドから資料をまとめる以外にも、日々の業務全般で Claude Tag を活用しています。彼女は Claude 専用のプライベート Slack チャンネルを持ち、同僚にタグ付けするのと同じ感覚で、別々のスレッドで Claude に @メンションして依頼をしています。そのチャンネルでは、Claude は貼り付けられたり添付されたりした内容を読み取り、Slack ワークスペースや公開ドキュメントを検索して、バックグラウンドで作業を進め、進捗を更新しながらチェックリストとして投稿します。Claude のアクセス権限は意図的に限定されており、[アクセスを許可された](https://claude.com/blog/agent-identity-access-model)チャンネルや文書のみを対象に動作し、必要なリソースへのアクセス権がない場合はその旨を知らせてくれます。

## 複数の Slack チャンネルに散らばった依頼を集約し、フォローアップする

新機能がリリースされると、営業担当者は通常、その機能をリクエストしていた顧客を把握し、連絡を取ります。こうした依頼は Slack やプロダクトフィードバックのハブを通じて寄せられ、数か月分の履歴の中に散らばっていることもあります。プロダクト戦略・オペレーションチームの Steph Soderborg は、ある新機能に関連するすべての依頼を集約し、顧客のためにその機能をリクエストしていた各担当者に直接通知する作業を、約26分で完了させました。

Steph はまず、検索対象、該当条件を1文で定義したもの、そして過去のリリース時に使った7件のリストという出力イメージの例を添えて、Claude にメッセージを送りました。「@Claude、これから[新機能]をGA(一般提供)します。Slackを検索して……この機能を自分の顧客のために要望した人を探してもらえますか……その人のSlackハンドルとチーム、要望のあったアカウント名、そしてSlack上の該当発言へのリンクも含めてください」

Claude は複数のチャンネルとワークスペース全体にわたって、約20通りの検索バリエーションを実行しました。プロダクトフィードバックハブへの直接アクセスがブロックされていたため、Slack上のクロスリファレンスを通じてハブ内の項目を洗い出し、社内の別のアシスタントが投稿していた一次リストも取り込んで重複を除去しました。集約されたリストは約26分で仕上がり、約24件のアカウントが含まれ、依頼者ごとに Slack ハンドル、チーム、アカウント名、元の要望へのリンクが1行にまとめられていました。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a91db2a994de3cf1ac088d2_805fca4a.png)

*Slack で特定の機能を要望したすべての人のリストを Claude に生成させている様子。この画像はユースケースを説明するために生成されたものであり、実際の情報は含まれていません。*

続けて Steph は、自分一人ではとても手が回らなかったであろう、より大きな集約作業を Claude に任せました。前週にエンタープライズ顧客から報告されたすべてのプロダクト上の問題について、何が壊れていたのか、すでに何が修正されたのか、複数の報告が同一の根本原因を指しているかどうかを整理した全体像が欲しかったのです。Steph は Claude に、インシデント、エスカレーション、サポート、プロダクトフィードバックを扱うすべての Slack チャンネルを読むよう指示しました。約50分後、Claude はプロダクト領域ごとに整理されたレポートを投稿し、約120件の未整理の報告を集約して、未解決の問題23件と解決済みの問題14件をまとめました。各項目には要約と元スレッドへのリンクが添えられていました。その後 Steph が確認作業を依頼したところ、Claude はさらに15件の問題を見つけ出しました。

Steph の見積もりでは、これだけの量の情報を精査・分析・統合する作業は、フルタイムでも1週間以上かかっていたか、あるいは着手すらできなかっただろうとのことです。Claude Tag を使うことで、依頼内容を整理するのに数分をかけるだけで、あとは Claude がバックグラウンドで作業を進めてくれました。

Steph もまた、プライベートチャンネルで Claude と作業しており、検索対象や該当条件、たいていは出力フォーマットの例まで含めた指示を最初にまとめて伝えています。Claude はワークスペースを検索し、招待されているチャンネルを読み、作業の進捗を投稿しながら進めます。フィードバックハブへのアクセスがブロックされている場合、Claude はアクセス可能な文書やチャンネルから関連情報を集めようとしたり、それらのチャンネルへのアクセス権限をリクエストしたりします。

## 法務レビューの迅速化

Anthropic の法務チームは、ブログ記事やランディングページ、メール、その他あらゆる資料を公開前にレビューしています。プロダクトのローンチが近づく数日間は、マーケティングチームがタイトな締め切りの中で、レビュー待ちの資料を何十件も抱えることがあります。それに加えて、通常のマーケティング資料もレビューキューに次々と流れ込んできます。1段落の SNS 投稿文から2,500語のブログ草稿、10個を超えるタブを持つ企画書、複数の接点にわたる複数バリエーションのメールシリーズまで、その種類はさまざまです。法務チームのプロダクトカウンセルである Molly Villagra は、Claude Tag がすべてのマーケティング資料を最初にチェックする専用の Slack チャンネルを作り、マーケティング法務レビューの所要時間を1日(あるいはそれ以上)から1資料あたり30分にまで短縮しました。

法務レビューを依頼する際、マーケティング担当者はそのチャンネルに文書へのリンクを投稿します。エンジニアリングの経験を持たない Molly は、そこに Claude 向けの具体的なルールと指示をあらかじめ設定していました。Claude は根拠のないマーケティング主張のような法務上の懸念点を見つけ出せるだけでなく、社内 Slack や社内ナレッジインデックス、公開されたウェブ情報にアクセスできるため、マーケティングコンテンツ内の事実関係の確認も手伝うことができます。問題点が見つかった場合、Claude はそれらを具体的な対応方法とともにリストアップし、依頼者と直接やり取りしながら対応を進めます。法務の承認が必要な残りの問題については、Claude が該当のプロダクトカウンセルにタグ付けし、担当者がフラグの立った記述を迅速に確認できるようにします。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a91db2a994de3cf1ac088cf_43aa7144.png)

*マーケティング担当者は、専用の Slack チャンネルに文書へのリンクを投稿することで法務レビューを依頼します。この画像はユースケースを説明するために生成されたものであり、実際の情報は含まれていません。*

例えば、あるニュースレターのレビューでは、Claude が3つの重要な指摘事項にフラグを立てた後、指示を受けることなく、数分のうちに社内文書から必要な情報を見つけ出して、そのうちの1件を自ら解決しました。Molly はこれをデフォルトの挙動にするため、マーケティング法務レビューチャンネルで @Claude とタグ付けしてこう依頼しました。「3つの指摘はどれも良い着眼点ですが、いずれもあなた自身で検証できる内容です。今後こうした点を指摘する際は、リアルタイムで検証することを試してもらえますか?」 Molly の依頼を受けて、Claude Tag はこの新しい指示を、今後のすべてのレビューで従うべき指示セットに追加し、チャンネル上のフィードバックをもとにリアルタイムで改善できるようになりました。

このフィードバックループに触発され、Molly は新たなルーティンを作りました。毎週金曜日に、その週の法務担当者からのフィードバックを Claude に確認させ、共有の指示セットの更新案を作成させて、自分が承認するというものです。

ここで紹介した各ワークフローは、Anthropic の社員にとって数時間から数日分の作業時間を節約するだけでなく、これまでは実現しえなかったプロジェクトを可能にしています。あなたのチームなら、最初にどんなワークフローやプロジェクトを Claude に任せますか?

Claude Tag は現在パブリックベータとして、Anthropic のファーストパーティサービス上で Team および Enterprise プランで利用できます。[claude.ai/admin-settings/claude-tag](https://claude.ai/admin-settings/claude-tag) からワークスペース向けにセットアップするか、[claude.com/docs/claude-tag](https://claude.com/docs/claude-tag) で詳細をご確認ください。

*本記事に記載の所要時間は、個々の社員が特定のタスクで経験した内容を反映したものです。結果はタスクの内容、接続されているツール、Claude Tag の設定方法によって異なります。*
