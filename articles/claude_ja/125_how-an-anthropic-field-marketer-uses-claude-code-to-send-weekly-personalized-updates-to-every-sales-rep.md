# Anthropic のフィールドマーケターが Claude Code を使い、毎週すべての営業担当者にパーソナライズされた最新情報を届ける方法
- 著者

  Adam Ward

マーケターとして私が直面してきた最大の課題の一つは、営業チームに現場で起きているあらゆることを常に把握してもらうことでした。多くのマーケターが経験する「ああ、そのイベントのことは聞いたことがなかった」(あるいはあの新しいホワイトペーパー、あのウェビナー)という廊下での会話には覚えがあるはずです。そしてその瞬間、最新の取り組みを営業担当者、ひいては顧客に共有する機会を逃してしまったことに気づくのです。

私の当初の解決策は、多くのマーケターにとって馴染み深いものでした。月曜朝の 15 分間の営業チームスタンドアップです。私は日曜の夜に社内各所からの最新情報をまとめ、見栄えのするスライドに仕立て上げ、それをミーティングで直接説明したうえで、資料を Slack で共有していました。これで完了、のはずでした。しかし、Claude を使えるようになると、こうしたやり方はどうにも手作業的に感じられるようになりました。チームが拡大し、複数の営業チームを支援するようになるにつれて、私のスライド作成ルーティンは追いつかなくなっていったのです。最新情報の有用性も下がっていきました。各チームにぴったり合う機会を選び出す時間がもう取れなくなっていたからです。

私が求めていたのは、Claude に作業をやってもらい、各営業担当者にとってより良い「プロダクト」――その担当アカウントに合わせ、マーケティング側のあらゆる取り組みと組み合わせた週次ダイジェスト――を作ることでした。

幸いなことに、私たちはマーケティングのハッカソンを開催していました。Claude Code を使って繰り返し行う業務プロセスやワークフローを作り直すための専用時間です。私はチームと集まり、この課題に 1 時間を充てました。それが決定的な転機になりました。ハッカソンのような、気軽で仲間同士から学べる機会があると、日々の業務の中ではなかなか捻出できない実験や探求の時間を確保できます。私たちのチームもその例に漏れませんでした。

## **コードを書く必要はなく、説明する必要がある**

同業のマーケターからよく聞かれる質問の一つが、「AI をどうやって使い始めればいいのか」というものです。私のアプローチ、特に Claude Code に対するアプローチは、まず自分が非技術者であることを Claude に説明したうえで、この特定の課題があること、そしてビジネス上の課題を深く理解しているプロダクトマネージャーとして自分を扱い、一緒にステップバイステップで進めてほしいと伝えることから始めます。私は声に出して考えるタイプなので、しばしば自分が課題を説明している音声を録音し、その書き起こしを Claude に渡します。そうすることで、Claude はビジネス上の文脈をすべて把握できます。

私たちのチームの週次 AE(アカウントエグゼクティブ)ダイジェストの場合、まず Claude にゴールを説明することから始めました。マーケティングで何が起きているか、そしてそれが顧客にどう役立つかを、各担当者に週次の Slack メッセージで伝える、というものです。次に、Claude が目指すべきテンプレートとして、架空の週次アップデートを書きました。営業担当者は行動指向であることを知っていたので、「今週のトップ 3」というリストから始めました。直近のイベントや最近のコンテンツなど、顧客と共有できる 3 つのアクションアイテムを掲載するものです。また、マネージャー向けロールアップ用に別のテンプレートも書きました。マネージャーは通常、個々のアカウントというより、チーム全体を俯瞰した視点を求めるからです。

次に、MCP 経由で Claude を BigQuery に接続しました。BigQuery は私たちのマーケティングチームにとっての信頼できる情報源であり、HubSpot、Clay、Salesforce からの詳細なデータへのインサイトを提供してくれます。まずはシンプルに始めたかったので、イベントとウェビナーに関する単一の信頼できる情報源から着手しました。各アップデートをパーソナライズするために、Claude に CRM から担当者のテリトリーを取得させ、Slack で共有された関連するアカウントの最新情報も取得させました。そうすることで、Claude はこの二つを突き合わせてパーソナライズされた週次アップデートを作成できます。

その後、マーケティング内の他のチームと協力してデータを拡充してきました。今ではブリーフィングにブログ記事や電子書籍、顧客事例、ウェビナー、さらにはパートナーエコシステムからのイベントといった新しいコンテンツも含まれるようになっています。

## **ユーザーからのフィードバックこそが本当のプロンプトエンジニアリング**

これを現場に展開するにあたり、まずテストグループとして協力してくれた一つの営業チームから始めました。10 人のグループに送るのであれば、エラーが起きても大事にならずに済みますし、そのグループはフィードバックを提供することにコミットしてくれていました。最初の送信の後、いくつか調整を加えました。

問題の中には単純なエラーもありました。例えば、ソースのシートに URL が記載されていないイベントがあると、Claude はもっともらしく見えるものの実際にはどこにもつながらない URL を作り出してしまうことがありました。私たちはすぐに「URL を捏造しない」というハードルールとしてプロンプトに書き込みました。今では、URL がソースのシートから一字一句そのまま取得されている場合にのみリンクが表示されるようになっています。その後のバージョンでは、リンクのないイベントはブリーフィングから完全に除外するようにしました。営業担当者が誰も登録できないイベントは、単なるノイズでしかないと気づいたからです。

最初の週の終わりまでに、プロンプトには 9 個のコンテンツルールが盛り込まれていました。それぞれが、担当者やマネージャーからのフィードバックにひもづくものです。あるナレッジワーカー向けワークショップに、あるエンジニアリング担当 VP が推薦されていたことを担当者が指摘したため、今では連絡先の役職がイベントの想定対象者と照合され、一致しない場合はコメントなしで除外されるようになりました。業界フィルターにより、小売業のアカウントが金融業界向けディナーの招待から除外されるようになりましたし、まだアカウントを持っていない入社したての担当者には、空のメッセージの代わりに短い歓迎メッセージが送られるようになりました。

他にもデータ上の問題がありました。マーケティングに携わる人なら誰でも、単一の信頼できる情報源を維持することがいかに難しいかを知っています。例えば、現場イベントのシートは、6 週間で 3 回も列の並びが変わりました。これに対応するため、実行のたびにまずシートのヘッダー行を読み込み、何かを作成する前に列のマッピングを確認するようプロンプトを変更しました。「C 列を見よ」とハードコードするのではなく、「イベント URL が入っている列を見よ」というような指示に変えたのです。

## **ビジネス全体へのダイジェスト展開**

これらの初期の取り組みの後、私が支援するすべてのチームにダイジェストを展開し、現在ではフィールドマーケティングが営業全体に向けてこれを運用しています。毎週月曜の朝、Anthropic の複数の営業セグメントに所属するアカウントエグゼクティブたちは、今週の優先アクション 3 つ、自分のアカウントに関連する現場イベント、既に登録済みの今後のウェビナーの連絡先、共有すべき関連マーケティングコンテンツ、その他のフォローアップ提案が列挙されたダイレクトメッセージを Slack で受け取ります。

各メッセージは受信者自身のアカウントリストから組み立てられるため、まったく同じものは二つとありません。このダイジェストは実際に効果を上げています。あるエグゼクティブディナーの登録数を 1 週間で 2 倍にできたのは、ひとえに適切な担当者に月曜の朝、適切なイベントが目に入ったからです。

Anthropic のビジネスデベロップメント担当者(BDR)たちが自分たち版のダイジェストを求めた際には、プロンプトを 1 つのフィールドだけ変更して複製しました。BDR はアカウントエグゼクティブとは異なる関係性で CRM 上のアカウントに紐づいているためです。プロンプトの構造とコンテンツルールはそのまま流用でき、BDR は 2 日以内に本稼働を開始できました。その後、カスタマーサクセスチームやアライアンスチームに対しても同様の取り組みを行い、営業以外のクロスファンクショナルなパートナー向けにマーケティング活動全体の概要も提供しています。

ビジネスがどれほど速く動いても、私のチームと私は、Claude の助けを借りて、営業担当者が月曜日を、今週何が起きているのか、どのアカウントとイベントを優先すべきかを正確に把握した状態で始められるようにしています。毎週月曜の送信はすべて完全にアーカイブされているため、どの担当者がどの日に何を受け取ったかを正確に確認でき、マネージャーはチーム全体のおすすめ情報を一つのロールアップで確認できます。今も私自身が送信内容に目を通していますが、システムはもはや私の承認を待ちません。数週間前に休暇を取った際も、月曜の送信は問題なく自動で行われました。

## **Claude を使い始める際のベストプラクティス**

以下では、Claude Code での自身の経験から得たヒントとコツを紹介します。

1. **すでに手作業で行っていることから、小さく始める。** AI で人々が何をやっているかという情報が溢れている中で、始めること自体が難しく感じられることがあります。私からのアドバイスは、自分が最も多くの時間を手作業で費やしている反復的なタスクを一つ選び、それを Claude に作り直してもらうことです。そうすれば、良い成果がどんなものかをすでに知っているので、アウトプットを判断できます。それでも課題が大きすぎると感じる場合は、Claude を思考のパートナーとして使い、ステップに分解しましょう。そして、他の人と共有するものであれば、まずは自分自身宛てに初期の実行結果を送るようにし、他の誰かに見られる前に自分でエラーに気づけるようにしましょう。
2. **平易な言葉で指示を書き、各文書をバージョン管理する。** 新しく入った同僚に説明するつもりで Claude に指示を伝えれば、あとは Claude がやってくれます。各アップデートを、変更点を一行でまとめたメモとともに番号付きバージョンとして保存するよう Claude に指示しましょう。そうすれば、過去の各実行結果を生み出したプロンプトの記録を残せます。私たちの場合は、同僚が自分の担当セグメント用に実行する Markdown ファイルで、最初は共有の Google ドキュメントから始め、編集する人が増えてから GitHub に移行しました。
3. **小規模でコミットしてくれるグループでパイロットする。** 私たちは最初のテストを、フィードバックの提供に時間を割いてくれることが分かっている少人数のアカウントエグゼクティブたちと行いました。彼らのおかげで、エラーを検出したり、カバー範囲の拡大やパーソナライズの方法について提案をもらったりすることができました。
4. **フィードバックを使ってプロンプトを改善し、修正のたびに明示的なルールとして組み込む。** マーケティングブリーフィングが実際に役立つようになったのは、受信者からフィードバックを共有してもらえるようになり、それぞれの修正が Claude に対する明示的なルールになっていったからです。

Claude は、以前は毎週日曜に何時間もかかっていた手作業のプロセスを自動化してくれましたが、このプロジェクトを通じて、私のチームと私が得たものは時間よりもずっと大きなものでした。私たちのアウトプットは、より個人に合ったもの、より役立つもの、そしてより測定可能なものになったのです。あなたなら、Claude でどのマーケティングプロセスを改善できるでしょうか?
