# Outtake が Claude でサイバー捜査官を構築した方法

*シリーズ **How startups build with Claude** では、スタートアップが AI で業界をどう変革しているかを紹介しています。この記事では、Outtake が偽のログインページから敵対的なネットワーク全体まで、デジタル上の脅威を検知・調査・解体する自律型サイバー捜査官をどのように構築したかを共有します。*

| The quick pitch | |
| --- | --- |
| Name | Outtake |
| Founded | 2023 |
| Founders | Alex Dhillon (CEO)、以前は Palantir のムーンショットチームに所属 |
| Growth | 年間経常収益を前年比 6 倍、顧客数を 10 倍以上に伸ばし、2025 年だけで 2,000 万件以上の潜在的サイバー攻撃をスキャン。 |

強力な安全対策や統制があっても、悪意ある行為者は AI の利用を一見無害な目的の裏に隠し、悪意を覆い隠すことができます。コード生成プラットフォームは説得力のあるログインポータルを作り出せますし、エージェント型の営業支援ツールはフィッシング攻撃の拡散を後押しし、画像生成能力は本人確認をなりすますことができます。従来のサイバーセキュリティ防御はこれに追いつくのに苦労しています。

「悪意ある行為者の立場に立てば、攻撃を仕掛けるにはまさに絶好の時代です」と、AI サイバーセキュリティプラットフォーム [Outtake](https://www.outtake.ai/) の創業者兼 CEO である Alex Dhillon 氏は語ります。「平均的な攻撃は AI によって実行が速くなるだけでなく、AI のおかげでより深いアクセスを獲得できるようになっています。」

Outtake は [デジタルトラストの攻撃チェーン](https://www.outtake.ai/blog/2026-digital-trust-industry-pain-report) 全体を一つの防御へと統合し、AI エージェントの集団を使って、大手 AI 研究所、大手ヘッジファンド、米連邦政府機関を含む顧客に向けられた脅威を自律的に検知・調査・解体します。

以下は、Outtake チームが最近、[Claude Code](https://code.claude.com/docs/en/quickstart) と [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) を使い、長時間稼働する自律型のサイバー捜査官である Recon Agent を Claude 上に構築した経緯です。

## **エージェント型の攻撃にはエージェント型の防御が必要**

企業を標的にするとき、攻撃者は概ね同じプロセスをたどります。公開データを武器化する → なりすましを罠として構築する → 内部システムを悪用する。このプロセスは AI によって加速されています。

何かに侵入する前に、攻撃者は組織やその役員、従業員に関する公開情報を収集します。

次に、その情報を餌に変えます。例えば不正なログインページを持つ偽のウェブサイトを作り、被害者を騙して認証情報を渡させるのです。こうした罠から得たアクセス権は、攻撃者が組織の最も価値ある機密資産に到達するために境界内へ入り込む助けとなります。

この 3 段階の流れは予測可能ですが、従来型のセキュリティツールは一度に一つの局面しか守れません。

- 脅威インテリジェンスツールは公開データの段階を監視し、
- ブランド保護ツールはなりすましを監視し、
- エンドポイントツールは内部システムを守ります。

Outtake の Recon Agent は、なりすましの背後にあるネットワーク全体を調査します。例えば単にクローンされたログインページを削除するだけでなく、エージェントはそのなりすまし事案から証拠を収集し分類します。

そこから「カスタマーサポート」を名乗る偽の Telegram アカウントのような、つながりのあるインフラへと手がかりをたどり、この敵対的なネットワークをグラフにマッピングします。エージェントの最終ステップでは、調査プロセスを説明するレポート、脅威行為者のプロファイル、そして攻撃者が行ったことの時系列を再構築したものが作成されます。

この高度なワークフローを実行するために、Recon Agent はコードを読み、書き、実行できます。悪意あるログインページと直接やり取りして、盗まれた認証情報が実際にどこへ送られるかを確認することさえできます。

こうした調査には、エージェントが長時間にわたって自律的に稼働することが求められる場合があります。エージェントのセッションは中央値で 16 分ですが、日常的に 1 時間を超えて延び、これまでの最長記録は結果を返すまでに 2 時間のエージェント作業を要しました。

## **Outtake が Claude で複雑な長時間稼働エージェントを構築した方法**

Outtake は Recon Agent をおおよそ 4 つの段階を経て構築しました。各段階は、良い調査とはどういうものかを理解し、その判断を徐々にエージェントへ委ねていくことがテーマでした。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6a60e7ad9916514322ed5ac4_3f776183.png)

### **ステップ 1: まず自分自身が専門家になる**

エージェントのどの部分を構築するよりも先に、Outtake のエンジニアたちは実際のサイバー調査を自ら行い、顧客やデザインパートナーからドメインの専門知識を引き出しました。

目標は「良い」とはどういうことかを定義することでした。この種の調査にとってそれは、どの証拠が重要か、どう整理すべきか、そして行動につながる結論と単なる推測とを何が分けるのかを見極めることを意味しました。その基準こそが、後のすべての段階で立ち返る固定の参照点になりました。

「長時間稼働するエージェントを構築するうえで最も重要なのは、*良いとはどういうことか？エージェントは何をすべきなのか？*を本当に理解することです」と、Outtake のエージェントプラットフォームのエンジニアリングリードである Jack Hayford 氏は語ります。「なぜなら最終的には、エージェントが毎回それを確実に実行できるようにすることが目的だからです。」

### **ステップ 2: Claude Code でプロトタイピングする**

当初、Outtake チームは従来型のエージェントフレームワークを使い、標準化しようとしていた調査を段階的に自動化していました。

しかし彼らはすぐに、Recon Agent が単純な捜査官であってはならないことに気づきました。コードを書き、実行し、その場でツールを組み立て、実際に悪意あるドメインとやり取りする必要があったのです。

「調査は一つひとつが異なり、深く技術的です」と Hayford 氏は言います。「エージェントにはコーディングの筋力と能力が必要でした。そして Claude Code は、こうした前提を実際に検証し、実験を重ねていくための強力な初期ハーネスでした。」

Claude Code でのプロトタイピングを通じて、彼らは核となる設計原則を鍛え上げました。オーケストレーションのレベルではエージェントを厳格に制約する(*「ドメインを調査するときは常に X、Y、Z を行う」*)一方で、判断が必要な場面では自由に即興させる、というものです。

### **ステップ 3: 本番グレードのハーネスへ移行する**

「Claude Code が導入していたパターンはとても気に入っていましたが、自分たちで作ろうとはしていなかった、より低レベルのプリミティブへの追加のアクセスが必要でした」と Hayford 氏は言います。

Recon Agent を本番環境へ持っていくための自然な次のステップは、Claude [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) を使うことでした。Claude Code から得たスキルやパターンを引き継ぐことで、チームは勢いを落とすことなく、エージェントループやセッション処理を一から作り直すことなしに、Recon Agent のメモリ、コンテキスト、ファイルシステムに対するより厳密な制御を手に入れることができました。

### **ステップ 4: エバルに駆動される緊密なイテレーションループを構築する**

攻撃者が防御ツールの存在を知った瞬間に適応してくるサイバーセキュリティの世界では、安価かつ迅速に反復できる能力が特に重要です。チームは最初からエージェントのエバルを組み込み、多数のシナリオを同時に実行できる強力なエバルスイートにたどり着きました。これにより、モデルのアップグレードやメモリシステム全体の作り直しといった大規模な変更を、安全かつ自信を持って行えるようになりました。

これはまた、チームがエージェントのループから自分自身を抜け出させることも可能にしました。例えば Recon Agent が調査を終え、持っていなかった何らかのツールがあればもっとうまくできたはずだと報告してきたとき、別のコーディングエージェントがその提案を読み取り、新しいツールを書き、それを試すためのテストシナリオを構築します。

人間が結果を確認するために介入するのは、まさに最後の最後だけです。エージェントはそのツールを使って調査をより良く行えたのか、そうでなかったのか。「私たちがボトルネックであり、こうした長く複雑なエージェントを構築するときには、フィードバックループを自動化することが非常に重要です。その方がずっと速いですし、開発者としてもずっと満足感があります」と Hayford 氏は語ります。

## **長時間稼働エージェントを構築して得た学び**

エージェントの黎明期には、開発者はエージェントが脱線しないよう、決め打ちで決定論的な、ステップバイステップの経路をあらかじめスクリプト化していました。今では、凝ったワークフローはハーネス、すなわちメモリ、ツール、スキル、ガードレールからなる支援的な環境に置き換えられつつあります。

Recon Agent の構築における Outtake チームの経験から得られた知見をいくつか紹介します。

### **ツール: ファイルシステムと bash があれば十分**

ファイルシステムは、コンパクション(圧縮)を生き延びるメモリを可能にします。エージェントには通常、非常に具体的で細やかなツールが与えられますが、書き込み、読み取り、コード実行の能力とともにファイルシステムを与えることは、エージェントが障害に対応する助けになります。

「こうした極めて強力でオープンエンドなツールや能力をエージェントに与えることは、大きな一歩です。ネットワークの不具合か何かでツールが失敗しているケースは何度も見てきましたが、エージェントは適切な回避策を自分で見つけて作業を続けました」と Hayford 氏は言います。「私たちが構築していたハーネスの残りの部分が十分に堅牢で、こうした強力でオープンエンドなツールを使って即興する余地をエージェントに残していたおかげで、それでも成功した結果にたどり着くことができたのです。」

### **プロンプトは提案にすぎない**

プロンプトは必要なときに柔軟性をもたらしますが、可能な限りハードコードすることが安定性を保証します。「時間とともに複雑になっていくこうした長時間稼働のエージェントを構築するとき、プロンプトは提案にすぎません」と Hayford 氏は言います。「エージェントが望みどおりに動かなかったとき、自然な反応はエージェントの最も可塑的な部分に追記することです。『X が起きたら必ず Y をする』とシステムプロンプトに滑り込ませるのは最初はうまくいくかもしれませんが、このエージェントが長く動き続けるにつれて、そのプロンプト内のあらゆる一語一句がいずれ無視されるようになるでしょう。」

正しいアプローチは、その可能性を織り込んで、エージェントが毎回必ず行うべきことを特定し、それをエージェントのガードレールの一部にすることです。「そうした事柄はプロンプトから引き抜いて、ハーネスの中に入れてください」と彼は言います。「そうすればエージェントはもうそれについて考える必要がなくなり、本当に力を発揮できる領域により多くのコンテキストの余地と注意を割けるようになります。」

*[Claude を導く際のベストプラクティス](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)、そして各手法のコンテキストコストと権威について詳しくはこちらをご覧ください。*

### **エバルは信頼性だけでなく速度のためでもある**

手作業の「振り返り」を、開発サイクルを引き締める自動エバルへのロードマップとして使いましょう。従来の見方では、エバルは信頼性のための品質ゲートです。しかし長時間稼働するエージェントにとっては、より大きな見返りはむしろ速度にあります。

初期の頃、Recon Agent が実行されるたびに、チームはその性能を手作業でレビューしていました。しかし、エージェントが行ったことすべてを記録した 30 分間のトランスクリプトを読むのは過酷な作業で、スケールしません。

「最新のエージェント開発において、出力を評価することはループの中で最もコストのかかるステップです」と Jack 氏は言います。

エバルとは、その振り返りを構造化し、採点可能で、自動化可能な形にしたものにすぎません。良いとはどういうことかを繰り返し可能なチェックとしていったんコード化してしまえば、エージェントを審判の席に座らせ、30 分間のトランスクリプトを読ませて実行を採点させることができます。

「完璧なケースを作るというアイデアのように感じられて、エバルの構築に不安を覚えるエンジニアもいると思います」と Jack 氏は言います。「どれほど公式で『完璧』かにかかわらず、最初から何らかの形のエバルを構築しておくことで、エージェントの構築はより速くなります。」

### **エージェントを守る**

[プロンプトインジェクション](https://www.anthropic.com/research/prompt-injection-defenses) は現実の脅威であり、エージェントをサンドボックスに入れる、あるいは鎧をまとわせることが不可欠です。Outtake チームが Claude を選んだ理由の一つは、プロンプトインジェクションに対する強さでした。

「Recon Agent の構築において、セキュリティは私たちにとって大きな注意点です」と Hayford 氏は言います。「ファイルシステムと bash を与え、敵対的な環境へ送り込んでいるため、私たちが解決すべき最も重要な問題は、エージェントの機能を妨げることなく、機微な内部システムからエージェントを隠せるような、いわゆるブラストボックスを構築することでした。」

彼らのアプローチは、エージェントが乗っ取られる可能性を前提としており、周囲のシステムは被害を封じ込めるよう設計されています。ただし、セキュリティのあり方はエージェントごとにその目的に応じて異なり、すべてのエージェントがブラストボックスの対象になるわけではありません。

Outtake は現在、エージェントがインターネットに手を伸ばすまさにその地点で信頼のレベルをスコアリングしており、エージェントがこれから触れようとしているものを評価するチェックポイントを実装しています。「このページはなりすましか? マルウェアか? 今まさにエージェントにプロンプトインジェクションを試みているのか?」 これはまさに、ますます敵対的になっていくインターネットを渡り歩くエージェントに必要な鎧なのかもしれません。

| Outtake チームからのベストプラクティス | |
| --- | --- |

| 複雑さの一つひとつは、それに見合う価値がありますか? | 最もシンプルに動くバージョンを見つけ、一つずつ自動化していきましょう。複雑さは、結果がそれを正当化する場合にのみ加えます。従来型ソフトウェアと同じ規律です。 |
| あなたのハーネスはワークロードに見合っていますか? | まず Claude Code で前提を素早く検証し、メモリ、コンテキスト、セッションに対するより低レベルの制御が必要になった時点で Agent SDK へ移行しましょう。エージェントループを自分で作り直す必要はありません。 |
| エージェントはどこで制約されるべきですか? | オーケストレーション層でガードレールをハードコードしつつ、その制約が低レベルの判断にまで踏み込まないようにしましょう。最良の結果が生まれるのは、その即興の余地からです。 |

## **これから**

Recon Agent は現在も稼働し、調査を実行し続けています。Outtake が Claude をどのように使って敵対的なインフラを大規模にマッピングしているか、さらに深く知りたい方は次をご覧ください。

- [*ウェビナー全編を視聴する*](https://www.anthropic.com/webinars/outtake-built-cyber-investigator-claude)。Outtake が Claude を使ってどのように脅威インフラを自律的に調査し、大規模にマッピングしているかについて、ライブデモとより深い議論をご覧いただけます。
- [*Recon Agent の実際の動きを見る*](https://www.outtake.ai/solutions/recon-agent)。単一のなりすましから脅威行為者の完全なプロファイルへとエージェントがどう進んでいくかを探ることができます。
- [*無料の Recon Agent アセスメントを受ける*](https://www.outtake.ai/recon-agent-assessment)。あなた自身の露出について、調査が何を明らかにするかを確認できます。
