# Claude Tag がチャンネル内での個人コネクタをサポートしました

[Claude Tag(ベータ版)](https://claude.com/product/tag)を使うと、Claude を Slack チャンネルに追加して、チームと一緒に作業させることができます。これまで Claude が利用できるのは[管理者がチャンネルに接続したコネクタ](https://claude.com/blog/agent-identity-access-model)のみで、多くの組織はこのリストを意図的に短く保っていました。アクセス権をチャンネル単位ではなく、個人単位で管理したいからです。

これからは、チャンネル内でのリクエストに対して自分自身の[コネクタ](https://claude.com/docs/claude-tag/concepts/settings-map)を Claude に使わせることができます。例えば、あなたのカレンダー、ドライブ、CRM で自分に割り当てられたアカウント、あるいはステージング環境へのデプロイ状況などです。[自分の Claude アカウントに接続済み](http://claude.ai/redirect/claudedotcom.v1.bd9ae4f6-0432-4354-822d-f70074fea02d/customize)であれば、チャンネル内でそれを利用できます。

コネクタへのアクセスを Claude に依頼した時点から、情報がどのように表示されるかを決めるのはあなた自身です。投稿前に各回答をレビューすることもできますし、オートモードを使って、Claude がレビューが必要なセンシティブな内容があると判断した場合を除き自動的に投稿させることもできます。Enterprise プランでは、管理者が全員に対してレビューを必須にできるようになります。

個人コネクタは、管理者にとってもガバナンスの選択肢を増やします。エージェント ID の下で共有ツール群へのアクセスを提供したり、チャンネルメンバーには個人コネクタのみを使わせて既存のロールベースアクセスに委ねたり、ツールごとに判断したりすることができます。

Claude Tag での個人コネクタは、Team プランで現在展開が進んでおり、Enterprise プランでも今後提供される予定です。

## **個人コネクタの使い方**

チャンネルで人々が必要とする情報の多くは、それぞれ自分自身のログインの裏側にあります。あなたのカレンダーで空いている時間、あなたが担当している進行中の商談、あなただけが開ける計画書などです。これからは、そうした情報もチャンネル内で依頼できるようになります。

例えば、GitHub に接続されたチャンネル #checkout-migration にいる Priya の例を見てみましょう。彼女は「@Claude 私の Google Drive のドキュメント『Checkout migration, Q3』を、これまでリリースした内容と照らし合わせて。まだ残っているのは何?」と尋ねます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6ab5827f9ff0fe18888b5382_08c194d9.png)

*Priya が #checkout-migration で Claude に、自分の計画とリリース済みの内容を照らし合わせるよう依頼している様子。チャンネルは GitHub にアクセスできる。ドキュメントは Priya だけが開ける。*

Claude はチャンネルの GitHub コネクタを通じて、マージ済みのプルリクエストを読み取ります。そのドキュメントは Priya だけが開けるものです。これまでであれば、Claude はここで作業を止めていたでしょう。

今では、Claude はチャンネルの作業とは別に、Priya の Google Drive コネクタを通じてそのドキュメントを読み取り、リリース済みの内容と残っている内容を投稿します。Priya の計画書はセンシティブな内容ではないため、彼女はオートモードを使い、Claude が比較結果を投稿する前にスクリーニングを行います。先にチェックしたいドキュメントについては、レビューモードに切り替えて、チャンネルに表示される前に回答を確認することもできます。

![](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6ab5827f9ff0fe18888b5385_d06075ed.png)

*同じスレッド。比較結果を返す Claude の回答と、投稿前に何が投稿されるかを示すレビュープロンプト。*

自分のコネクタを通じて Claude が行うすべての操作は、現在ダイレクトメッセージでの作業と同様に、そのツール自体のログにあなたのアカウントの下で記録されます。チャンネル自体の作業は、セキュリティチームが既に把握しているサービスアカウントの下に残ります。

ダイレクトメッセージで自分のコネクタを使う場合と同様に、Claude が何にアクセスできるか、チャンネルに何が見えるかを決めるのはあなた自身であり、いつでもコネクタの接続を解除できます。

## **チャンネル自体のコネクタが重要な場面**

個人コネクタは、無人の状態では動作しません。スケジュール実行されるルーティンや、Claude が自発的に開始する作業は、管理者がチャンネルに接続したコネクタを使用します。無人での操作や、チャンネル全体が依存する操作に必要なツールには、共有コネクタを使うべきです。

例えば、[#on-call チャンネルに Claude を追加して、CI のトリアージと対応を支援させたい](https://claude.com/blog/ai-ci-cd-on-call)場合があるでしょう。ランブックやモニタリングツール、デプロイ履歴への共有コネクタを設定しておけば、Claude は(業務時間外でも)問題を特定し、対処を支援できます。

個人コネクタのみに依存するチャンネルは、密に監督された作業に向いています。例えば、RFP への回答を共同で作成する場合、チャンネル全体には提供されていない価格情報などのセンシティブなソースからデータを取得する必要があるかもしれません。Claude が投稿する内容は、チャンネル内の全員に見えることに注意してください。

## **今後の展開**

インストールは不要です。あなたのリクエストが自分のコネクタのいずれかを必要とする場合、Claude は最初の一回だけ確認を求め、その後はスレッド内でそれを使用します。

チャンネルで @Claude に、自分だけがアクセスできる情報を尋ねてみてください。[Claude Tag](https://claude.com/product/tag) について詳しくはこちらをご覧ください。
