# Anthropic のあるセールス担当者が、チームのワークフローを Claude Code でつくり直した方法

2024 年に Anthropic に参加するまで、Jared Sires はコードを 1 行も書いたことがありませんでした。そして、書く理由もありませんでした。彼はスタートアップのアカウントエグゼクティブだったからです。

急成長中の企業ではよくあることですが、Jared が抱える顧客名簿はあっという間に 600 件から 700 件に膨れ上がりました。1 日に 10〜15 件の顧客コールをこなし、アカウントリストが増え続ける中、Jared は毎晩夜の 9 時や 10 時まで自席に座り続け、顧客からのメールに返信していました。

「自分のインボックスを管理するのはほぼ不可能でした」と彼は言います。「しかも、その上でアウトバウンドまでやろうとすると、どこに集中すればよいのかすら分からなくなるんです」

Jared は助けを求めて Claude Code に頼りました。コーディング経験がないまま、彼は CLAFTS——*Claude Drafts* の略——を作り上げました。これは Gmail の中で動き、Claude API を使って顧客メールへの返信ドラフトを生成するアプリケーションです。何度も反復を重ねましたが、最終的に Jared の見積もりでは、CLAFTS は彼に毎日 2〜3 時間の時間をもたらすようになりました。彼が翌朝それを Slack で共有すると、24 時間以内にセールス組織内の他のメンバーも使い始め、同様の効果を得るようになりました。

これが Anthropic における Jared の役割を変えるきっかけになりました。現在の彼は go-to-market チームのプロダクトマネージャーで、Anthropic のセールス組織における運用上の課題を見つけ出し、それを解決する Claude ベースのソリューションを構築することだけに専念する役職に就いています。この新しい役割の中で Jared は、顧客とのコミュニケーションを自動化したり、コール前に顧客の背景情報を調査したり、ミーティングの文字起こしからフォローアップメールを生成するツールを構築してきました。さらにそれらを [Claude Cowork](https://claude.com/product/cowork) のプラグインとしてパッケージ化し、セールスチーム全体で使えるようにしています。

彼は自身のキャリアにおけるこの変化を「これまでで最もエンパワリングな経験」と表現しています。

ここでは、Jared が大量のインボックスを Claude でどう捌いてきたか、次に何を作っているのか、そして GTM チームが彼のアプローチから学べるベストプラクティスを紹介します。

## **管理業務に埋もれていたセールス担当**

メールの量は、Jared がアカウントエグゼクティブとして直面していた唯一の課題ではありませんでした。Anthropic は 24〜48 時間ごとにプロダクトの変更をリリースしており、顧客からの質問は最新の細部に着地しがちです——バッチ API の SLA、プロンプトキャッシングの割引、モデルの価格、SDK の挙動、といったものです。それらにきちんと答えるためには、Slack や Google Docs、社内ナレッジベース、開発者向けドキュメントを横断的に検索しなければならず、しかもそれを日ごとに、少しずつ異なる事実関係のもとで何度も繰り返す必要がありました。

「技術ドキュメントを顧客に伝え直さなければならないというのは、なかなか難しいことなんです。とくにここ Anthropic では、プロダクトが非常に速く進化しますから」と Jared は言います。

Claude を使った彼の最初の実験のひとつは、狭く実用的なものでした。Apps Script（Google の軽量な開発プラットフォーム）と Claude を使い、Jared は社内システムからプロダクトの利用データを引き出し、Claude に毎朝、利用量がどれだけ速く伸びているかでアカウントをランク付けさせていました。

「毎日 Claude は、利用量に基づいて、その日に注力すべき相手の簡潔なブリーフを作ってくれました」と彼は言います。彼の名簿に並ぶ 700 のアカウントを前にして、この毎日のブリーフは、アウトバウンドに使う時間をどこに振り向けるかを判断する助けになりました。

## **CLAFTS の開発**

より厄介な課題は、Jared のインボックスと、彼がメール返信のために費やしていた夜遅くまでの時間でした。

Claude Code を使って、彼は自分の声色で顧客メールへの返信ドラフトを書くシステムを開発し始めました。「Claude Code は、末尾に "code" という言葉が付いているせいで、最初は始めるだけでも少し怖く感じました」と彼は言います。「ですが、しばらく使ってみると、それが自分のコンピューターに接続して、その中のファイルについて回答できるツールであることのパワーが分かりました」

CLAFTS はおよそ 4,300 行のコードの上に構築されていて、そのほとんどすべてが Claude Code によって書かれています。共有された Google Drive フォルダや他のサードパーティツールからコンテキストを引き出し、Web 検索を介して Anthropic 公開ドキュメントを参照し、Jared の文体に合わせます。1 日の終わりに彼がドラフトフォルダを開く頃には、レビュー待ちの返信が並んでいる、という仕組みです。

Anthropic がプロダクト変更をリリースするたびに、ドキュメントがそれを反映し、Claude は次のドラフト時にその変更を取り込みます。「Claude は Web 検索を使って、私たちのウェブサイトにある最新のドキュメントを理解し、メール生成時にその素材を参照することができます」と Jared は言います。「私はそれを全部頭に入れておく必要がないんです」

そのままでは、Claude の文章は長めで、ヘッジ表現が多くなる傾向があったため、Jared はシステムプロンプトを練り直し、ドラフトが自分の文体に近づくよう調整しました。「CLAFTS のシステムプロンプトについては、自分用の文章を生成させるためにおそらく数百回は反復してきました」と彼は言います。

次に、彼は CLAFTS Tones という機能を開発しました。これはパターンマッチングを使って、相手との関係性ごとに彼の声色を模倣するものです。顧客、同僚、家族との会話はそれぞれ違った調子で読まれるので、ドラフトはそれに合わせて調整されます。

Jared はこの機能をテストするため、自分のプライベートアカウントに向けて、徐々に怒りの度合いが上がっていく一連のメールを書きました。Claude はそのトーンをまず拾い上げ、ある時点で続行を拒否しました。

「Claude がそれを模倣し始めて、あるところで拒否反応を出すようになりました。Claude が顧客に向けた怒りのメールは生成したくない、ということです」と彼は言います。「そのとき、CLAFTS Tones が機能していると確信しました」

### **CLAFTS のインパクトを測る**

CLAFTS は Jared に週あたり 10〜15 時間の時間をもたらしていますが、彼が最も大切にしているのは、仕事の正確さに関する変化です。Claude がドラフトのたびにドキュメントから現在のプロダクト詳細を引き出してくれるおかげで、顧客が受け取る回答は、Jared がたまたま記憶していたものではなく、直近にリリースされた内容に紐付けられます。

「CLAFTS が無かった頃は、顧客と時間を過ごすことよりも管理業務に時間を使っていた、という感覚がありました」と Jared は言います。「CLAFTS が入ってからは、自分が本当にやりたかったこと——つまりセールス——により多くの時間を使えるようになりました」

## **Anthropic の GTM ツールキットを広げる**

Jared 以外にも、深夜過ぎまで定常的に顧客対応のメールを書いていた BDR の John Albert が CLAFTS の共同開発を手伝いました。ビジネス開発チームの残りのメンバーは、自分たちのチームメイトが毎日数時間を取り戻しているのを目の当たりにして、CLAFTS に乗ってきました。そこから先は、ほとんどが彼ら自身による布教でした。

Jared が次に作ったのは、彼のカレンダーを両端で挟む一連の [skills](https://docs.claude.com/en/docs/agents-and-tools/agent-skills/overview)——daily brief と daily recap でした。

朝になると、daily brief skill は彼のカレンダーを読み、その日に会う相手について Web 検索を実行し、最初のコールの前にトーキングポイントを生成します。この skill は [MCP サーバー](https://www.anthropic.com/news/model-context-protocol)を通じて Google Calendar と CRM データに接続し、各顧客に関する関連情報を引き出します。

そして 1 日の終わりには、daily recap skill が Google Docs とミーティングノートからフォローアップメールのドラフトを生成します。これは CLAFTS と似た働きです。

「この 2 つを組み合わせると、Claude が日々のタスクを管理してくれるようになります。これは実質的にエージェントになるということです」と彼は言います。

Jared の仕事は今、エージェント領域にさらに踏み込みつつあります。彼は [Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) を試したり、ある Claude の実行結果が次の入力に流れ込むようなワークフローのチェーンを試したりしています。

Claude Code で作ったツールが、彼がサポートしている広範なチームに行き渡るようにするため、彼はそれらを Claude Cowork で出荷しています。skill と MCP コネクターを 1 つのプラグインにまとめ、誰もが数分でインストールできる形にしているのです。

Sales プラグインをローンチしてから数ヶ月のうちに、Anthropic のセールス組織のおよそ 80% がそれを使うようになりました。残り 20% は主に新入社員で、Jared はそこを次の課題と捉えています。なぜなら、これらの skill はそもそも、人々がより速く立ち上がれるよう支援するために作られたものだからです。

プラグインができる前は、新入社員はそれぞれ自分のワークフローを編み出すのに数週間かかっていました。今や新入社員は入社初日にそれをインストールするだけで、自分たちが使うツール——Salesforce、Intercom、Gong、Google Calendar、Gmail、Google Drive、BigQuery——にあらかじめ配線済みの 20 以上の skill が使える状態になっています。

セールスチーム用プラグインを支える 2 つの skill があります:

1. `/customer-context` は、これらすべてのソースを横断する 360 度のアカウントビューを、およそ 90 秒で引き出します。
2. `/pipeline-management` は、リスクのある案件、フォーキャストの指針、進行のための推奨アクションを可視化します。

このパッケージは Cowork のスケジューリング機能とも統合されており、担当者は skill を自動で実行するキューに積むことができます。

「私たちのセールス担当は、いろいろなアプリケーションをアップデートしに行く代わりに、本当に意味のある会話に戻ってくることができます」と彼は言います。

## **次に作るものをアーキテクトする**

Jared の役割は、ツール群の進化と並んで変わってきました。GTM Architect として、彼は今、プロダクトエンジニアと一緒にデザインカンバセーションに参加し、Anthropic のセールスチーム向けの新しいツールをかたちづくる手伝いをしています。

「技術の壁が溶けていくのに合わせて、私はより多くのプロダクトを設計でき、シニアエンジニアに最終工程の実装を手伝ってもらえる、という感覚があります」と Jared は言います。「自分自身を拡張して、より多くのことができるようになっているんです」

彼自身と似たようなものを作れるかどうか迷っているセールスの人に向けた彼のアドバイスは、Claude Code を開き、自分を遅らせているタスクを 1 つ見つけ、Claude にそれを解決するソリューションをどう作ればよいかを聞いてみることだ、と言います。

「1 年前の自分に、Anthropic で go-to-market プロダクトマネージャーになるよ、と言ったら、かなり驚いたはずです」と彼は言います。「そういう会話に入れるだけの技術力は、もともと自分には無かったのですから。Claude を使えば、自分自身の日常のワークフローを良くするだけでなく、より広いチームのワークフローまで改善するものを設計し、構築できます。よりクリエイティブに、よりストラテジックに働く余白があるし、もう元には戻れません」
