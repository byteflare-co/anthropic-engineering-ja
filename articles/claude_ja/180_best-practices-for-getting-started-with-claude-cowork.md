2024 年、私たちはチャットウィンドウの中で Claude を使っていました。質問すれば答えが返ってきますが、その答えを実際に役立つものに仕上げるのは自分の仕事でした。2025 年には Claude Code によって、エンジニアたちが他の私たちが少しうらやましくなるほどのペースでプロダクトを出荷できるようになりました。

そして今年、私たち全員が [Claude Cowork](https://claude.com/product/cowork) で追いつくことができます。

私は昨年、チャットでは対応しきれない長く複数のステップからなるタスクのために Claude Code を使い始めました。1 週間のうちに、ターミナルが何かも知らなかった状態から、[30 分かかっていたタスクを 30 秒で終わらせる Claude Code のワークフロー](https://claude.com/resources/articles/how-anthropic-uses-claude-marketing)を構築するまでになりました。当時はまだ Claude Cowork が存在しなかったので、技術的ではない仕事に Claude Code を使っていたのです。

今では、私の仕事の 90% は [Claude Cowork](https://claude.com/product/cowork) の中で行われています。この記事では、自分のタスクのうちどれが Claude Cowork に向いているかを見分ける方法を紹介し、私自身の仕事からの実例を順に説明したうえで、約 10 分で最初の成果物を完成させるところまでご案内します。

## チャット、Claude Cowork、Claude Code の使い分け

あなたの仕事が、メール、スライド、スプレッドシート、ドキュメント、会議、そして「これの要約をまとめてくれる?」といった非技術的なナレッジワークであれば、Claude Cowork はあなたのためのものです。コードの書き方を知る必要はありません。「エージェント」が何なのか、どうやって作るのかを知る必要もありません。

もしこの 2 年間、100 個もの他のタブやファイルに混じって AI チャットのタブを開きっぱなしにし、プロンプトや質問をコピー＆ペーストで貼り付けては、回答をまたコピー＆ペーストで取り出していたなら、あなたはすでに Claude Cowork の使い方を知っています。それからコピー＆ペーストを取り除いたものが Claude Cowork です。

チャット、Claude Cowork、Claude Code、Claude Design をはじめ、Claude が登場するあらゆる場所は同じ Claude モデルで動いています。これらは異なる種類の仕事に使い分ける別々のワークスペースですが、中で動いているモデルはすべて同じです。どれをいつ使うべきかを考えるためのフレームワークは次のとおりです。

- **チャット**は、ナレッジワーカーが Claude に初めて触れる入り口になることが多いものです。手元にあるものを Claude に持ち込みます。ファイルをアップロードしたり、テキストを貼り付けたり、状況を説明したりして、答えを得ます。チャットは、答えを得る、ブレインストーミングをする、考えを声に出して整理するためのものです。
- Claude デスクトップアプリの **Claude Cowork** は、これを逆転させます。仕事を Claude のところに持ち込むのではなく、Claude をあなたの仕事のところに連れてくるのです。コンピュータ上のフォルダを指定し、普段使っているアプリに接続し、何をしてほしいかを伝えます。Claude Cowork では、望む結果を説明してその場を離れ、戻ってきたときには仕事が完成しています。
- **Claude Code** は、ソフトウェアを構築・出荷する開発者向けに作られています。あなたの仕事がコードの中にあるなら、まずはそちらから始めてください。

Claude Cowork と Claude Code が内部では同じ[エンジン](https://code.claude.com/docs/en/how-claude-code-works)で動いていることは、あまり知られていません。

### Claude Cowork はいつ使うべきか

Claude Cowork とチャットをいつ使い分けるかは、多くの人がつまずくポイントです。そこで、私の経験則を紹介します。

- **チャットを使う**のは、質問、説明、ブレインストーミング、直感的な確認など、やりたいことが数回のやり取りで収まる場合です。
- **Claude Cowork を使う**のは、必要なものが成果物である場合です。たとえば、誰かが開くファイル、誰かがプレゼンするスライド、整理すべきスプレッドシートなどです。複数のステップからなるもの、複数のファイルやファイル形式、あるいは複数のアプリにまたがるもの、質問というよりタスクと表現するようなものにはすべて Claude Cowork を使いましょう。Claude Cowork では、あなたは Claude に仕事を*委任*しているのです。

境界線がどこにあるかを示す例をいくつか挙げます。

| 質問やタスクの例 | 使うもの |
| --- | --- |
| ビジネスレビュー会議では何を取り上げるべき? | チャット |
| この Google Drive フォルダにある過去 3 か月分の議事録を読んで、私たちのテンプレートを使って QBR のスライドを作って。 | Claude Cowork |
| VLOOKUP はどうやって使うの? | チャット |
| 私のスプレッドシートを確認して、VLOOKUP をすべて INDEX MATCH に置き換えて。 | Claude Cowork |
| このページのより良い title タグと meta description を提案して。 | チャット |
| このシートにある 30 ページ分の新しい title タグと meta description を使い、CMS コネクタ経由で更新して。 | Claude Cowork |

最もよくある間違いは、何でもチャットで済ませてしまい、Claude Cowork がもたらす違いを一度も実感しないことです。その逆の間違いは、Claude Cowork で単発の質問を処理し、チャットなら 5 秒で答えられたはずのものを待ち続けることです。

### Claude Cowork 向きのタスクの 5 つの要素

使い始めたばかりで、どのプロジェクトを Claude Cowork に委任すればよいかわからない場合は、このチェックリストに照らしてみてください。5 つすべてを満たす必要はありませんが、良い候補はいくつかに当てはまります。

1. **入力が複数ある。** 複数のファイル、フォルダ全体、あるいはファイルといくつかのコネクタ。入力が 1 つだけなら、たいていはチャットで十分に対応できます（それでも試してみるべきではあります）。
2. **ファイルが出力される。** 添付する、プレゼンする、共有する、別の用途に転用するといった成果物が必要です。ドキュメント、スライド、スプレッドシート、CSV などです。
3. **繰り返し行う。** 単発のものでも構いませんが、定期的なタスクこそが最適な領域です。デスクに着く前に実行されるようにスケジュールすることもできます。
4. **何が良い出力かをすでにわかっている。** 出力の形に慣れているので、その出力が正しいのか、間違っているのか、70% の出来なのかを 15 秒で判断できます。
5. **中間部分が退屈な作業である。** 思考が必要なのは最初（何が欲しいかを決める）と最後（それが正しいかを判断する）です。その間にあるもの（抽出、集約、突き合わせ、再フォーマット）はすべて任せられる部分です。

## Anthropic での私の Claude Cowork の使い方

私は Anthropic でグロースマーケティングを担当しているので、私の例はマーケティング寄りです。コピーするワークフローを探すつもりでこれらを読まないでください。それは長い目で見ると役に立ちません。それよりも、それぞれの例が上のチェックリストのいくつかの項目にどう当てはまっているかに注目してください。それこそが、あなた自身の Claude Cowork ワークフローで探すべきパターンだからです。

### デイリーブリーフィング

マーケターが毎日受け取る Slack チャンネルやメールの量は圧倒的です。私は毎朝 6 時に実行される「デイリーブリーフィング」タスクを用意しています。Claude Cowork は私の Slack と Gmail に接続されており、プロンプトで未読メールと私が気にかけているチャンネルを確認し、それらをカテゴリに分類して、短いレポートを作成するよう指示しています。

![](https://assets.claude.com/481d42a0f045f1e716e1f9f6f6571476157f2aab.png)

このレポートには、確認すべき事項の TL;DR、種類別にグループ化されたフラグ付きメール、チャンネルの要約、そしてマーケティングに影響を与えた可能性のある夜間のプロダクト関連インシデントがまとめられています。Slack とメールに溺れている人なら誰でも、このワークフローの何らかのバージョンを実行できます。

### 予算ペーシング

私の仕事には、パフォーマンスマーケティングの予算ペーシングも含まれています。退屈で面倒なので、誰もやりたがらない種類の仕事です。多くのパフォーマンスマーケティングチームは、目標に対するペースを見積もるために、日々の支出とランレートを Google スプレッドシートで管理しています。各チャネルから日々の支出を手作業でエクスポートしてシートに貼り付けるか、データの抽出・変換・ロードを代行するサードパーティツールにお金を払うかのどちらかです。

![](https://assets.claude.com/4b0a081e502fc09bfc252fd2c23ea16347bc8dfd.png)

Claude Cowork では、Google 広告と Meta 広告に接続し、デスクトップアプリ内にライブアーティファクト（要するに HTML のダッシュボード）を作成しています。これが日々の支出を自動的に取り込み、ペーシングを計算してくれます。キャンペーンをどうフィルタリングするか、何に注意すべきかも、普通の言葉で Claude に伝えるだけで済みます。

これを上のチェックリストに照らしてみましょう。入力は複数（すべてのチャネルの支出）、ファイルが出力される（この場合はダッシュボード）、私は何度も繰り返し実行し、中間部分は自分では絶対にやりたくない、ダウンロードしてコピーして貼り付けるだけの魂をすり減らす単純作業です。広告プラットフォームはコネクタ経由で統合されているので、このダッシュボードはいつでも更新できます。

### レポーティング

大量の CSV をエクスポートしてピボットテーブルを作ったり、ファイルを手作業で結合したりする代わりに、私は Claude Cowork を Google Search Console に接続しています。Claude は私が気にしているもの（クエリ、国、ページ）を取得し、それを 1 つのシートにまとめます。手動でデータをエクスポートした場合の Google のデフォルトでは、ディメンションごとに 1 つの CSV になってしまいます。

![](https://assets.claude.com/e7b3f3c2e2b7d73dd1e4b95da1889b53df0cfb57.png)

また、何に注目すべきかというコンテキストも Claude に与えています。たとえば、直近 7 日間とその前の 7 日間を比較する、特定の国だけに絞り込む、大きく変動したものにフラグを立てる、私が望むテンプレートでレポートを書く、といったことです。そこから、何かを微調整したり、Claude に追加の質問をしたりできます。

![](https://assets.claude.com/a4239b970dff8e06581af6dacb876de8c9e917af.png)

Claude Cowork のスケジュール機能により、これは毎週自動的に実行されます。以前はレポーティングに週 30 分ほどかかっていましたが、今では 5 分で済み、その時間を私の判断が必要な部分、つまり欠けているコンテキストを補ったり、注目ポイントを練り上げたりすることに使っています。

これらは私の Claude Cowork の使い方のほんの一部であり、可能性のごく一端にすぎません。プラグイン、スキル、ローカル MCP、[Dispatch](https://support.claude.com/en/articles/13947068-assign-tasks-from-anywhere-in-claude-cowork) にまたがる別の複雑なユースケースについて[より詳しく解説した](https://www.linkedin.com/feed/update/urn:li:activity:7448056387772833795/)私の別の記事もぜひご覧ください。さらに多くのベストプラクティスを紹介しています。

## Claude Cowork との最初の 10 分間

初めてアプリを開きますか? 始め方は次のとおりです。

1. Claude デスクトップアプリを開き、Claude Cowork タブに切り替えます。
2. Claude に作業材料を与えます。いくつかのファイルをドロップする、コンピュータ上のフォルダを指定する、あるいはよく使うアプリ（Slack、Gmail、Notion、CRM など）に接続します。Claude Cowork の出力が平凡になるか素晴らしいものになるかの違いは、プロンプトにあることはほとんどなく、Claude が作業するのに十分な豊富なコンテキストを提供しているかどうかにあります。
3. 望む結果を Claude に伝えます。最終的に欲しい成果物を説明し、必要なコンテキストを提供します。
4. よく知っている実際のタスクから始めます。Claude がどこに強く、どこであなたからのコンテキストを必要とするかがすぐにわかりますし、そのタスクで何が「良い」のかもすでにわかっています。
5. 作業を始める前に、Claude に質問させます。これは私が身につけた習慣の中で最も役に立っているものです。プロンプトの一部に次の文を含めてください。*Before we begin, repeat my ask back to me so we're aligned, then ask me as many clarifying questions as you have.*（始める前に、認識を合わせるために私の依頼内容を復唱し、そのうえで確認したいことをできるだけ多く質問してください。）

これにより、どの期間を対象にするのか、ここでの「良い」とは何を意味するのか、Claude は知らないがあなたは知っているエッジケースは何か、といった、自分では指定しようと思わなかった事項が浮かび上がります。陥りがちな罠は、自分にとって明らかなことを Claude もすでに知っていると思い込むことです。最初に 5 つの質問に答えるのにかかるのは 30 秒です。同じ抜け漏れを後から見つけると、時間もトークンも消費しますし、修正するのも面倒です。

それでも何を任せればよいかわからない場合は、Claude に聞いてみましょう。Claude にはメモリがあり、過去の会話を検索できるので、あなたが最も頻繁に行っているタスクはどれか、Claude Cowork で試すべきタスクはどれかを尋ねることができます。

![](https://assets.claude.com/165fc0fddf6ae311f0b915883469ee1982e4bbc5.png)

### 今でもチャットを使う場面

ポジショニングの課題について話し合ったり、アイデアを確定する前に厳しく検証したり、なぜうちの犬がベッドをなめ続けるのかといった取りとめのない質問をしたりするときには、今でもチャットを大いに使っています。

要は、チャットが「古い」ものだということではありません。チャットは出力が頭の中の考えであるときのためのもので、Claude Cowork は出力が誰かに渡すものであるときのためのものです。

## 何かを作ってみよう

毎週行っている繰り返しのタスクを 1 つ選び、[Claude Cowork](https://claude.com/product/cowork) で試してみて、何が返ってくるかを確かめてください。最初のいくつかのタスクは少しぎこちなく感じるかもしれませんが、何度か試すうちに、「これはどう使えばいいの?」から「次は何を任せようか?」へとすぐに変わっていくはずです。
