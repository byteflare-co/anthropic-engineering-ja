# Built with Opus 4.7 Claude Code ハッカソン受賞者の紹介

先週、私たちは [Claude Build Day](https://cerebralvalley.ai/e/claude-startups-build-day) を開催しました。これは最新のハッカソンで、ビルダーたちがサンフランシスコに集まり、Claude Opus 4.8 を使って自分たちのアイデアを形にしました。

彼らが何を作り上げたのかを楽しみに待ちつつ、Built with Opus 4.7 ハッカソンの受賞者たちに、自分たちのプロジェクトについて話を聞きました。今回のプロジェクトは、医療研修、エレクトロニクス修理、コンピュータサイエンス教育、インタラクティブな遊び、住宅修繕、そして工場メンテナンスといった領域に取り組んだものでした。

受賞者の皆さん、そして参加してくださったすべての方々におめでとうございます！彼らのアイデアが、あなたへのインスピレーションになれば幸いです。

## 第 1 位：[Medkit](https://bedirhankeskin.com/)、Bedirhan Keskin

イスタンブール在住の Bedirhan Keskin は、医師からソフトウェアエンジニアに転身した人物で、Claude Managed Agents を使って Medkit を構築しました。Medkit は医療研修医や若手医師向けの学習ツールで、ゲーミフィケーションされた医療クリニックの中で実際の患者対応をシミュレートします。

「救急外来で 50 人の患者が待っている中、たった一人で立ち向かい、医学部で一度も実践したことのない症例があると気づいたとき、結局そういう症例をリアルタイムで本物の患者に対して練習することになってしまうのです」と Bedirhan は語ります。

Medkit を使うと、医学生はシミュレートされた患者の診断と治療を練習できます。問診を取り、検査をオーダーし、画像を読影し、診断を下し、治療を処方するまでをこのツールで行うのです。最後には、エージェント型の採点者が、評価試験委員と同じく公開されている臨床ガイドラインに照らして、診療全体を評価します。

Bedirhan は Medkit を 4 つの異なる Claude Code セッション（音声エンジン、コンテンツ生成、3D ゲームレイヤー、コアアプリ）にまたがって構築し、それぞれのコンテキストをクリーンに保ちつつ、すべてを同時に進めました。彼は「タイピングするな、話せ」というアプローチに従い、ほぼ完全に音声で作業を進めました。

Medkit はすでに注目を集めており、イスタンブールに拠点を置く 3 つの医学部と 1 社の製薬企業が、近いうちにパイロット運用を開始する予定です。

**他のビルダーへのアドバイス：** Claude を、単なるコーディングエージェントとしてだけでなく、思考のパートナーとして扱いましょう。

Bedirhan の最初の本能は音声エンジンを自前でホストすることでしたが、Claude はより速く進めるためにクラウドプロバイダーを使うことを提案しました。「Claude について最も価値を感じているのは、単なるコードジェネレーターではなく、自分一人では見落としていた選択肢を一緒に見せてくれる思考のパートナーである、ということです」と彼は言います。

[*Medkit on Github*](https://github.com/bedriyan/medkit-app)

## 第 2 位：[Wrench Board](https://wrenchboard.cloud/)、Alexis Chapellier

フランスの Reignier-Ésery 出身の Alexis Chapellier は、エレクトロニクスを修理して長年を過ごした後、修理工房向けの AI 搭載管理プラットフォーム [RepairMind](https://repairmind.io/) を生み出しました。Opus 4.7 ハッカソンでの彼のプロジェクト [Wrench Board](https://wrenchboard.cloud/) は、独立系の技術者が複雑な修理に取り組むのを助けます。ユーザーは回路図とボードビューを投入し、症状を記述すると、エージェントが統合された電気回路グラフを作成し、それを推論し、プローブを当てるべき正確なパッドを指し示し、測定値を読み取り、問題を診断するまで仮説を更新していきます。

Alexis は Wrench Board を Claude Design でプロトタイピングし、アプリの責務（デザイン、回路図の取り込み、ボードビュー、診断エージェント）を分離して、それぞれについてまず仕様、続いてプランを作成しました。実装は Claude Code のマルチエージェントモードで進め、デバッグ中はあらゆるステップで 5～6 体のエージェントを並列に走らせてベンチマークし、各ドメインに専任のエージェントを 1 体ずつ割り当てました。

Alexis の大きな賭けは、Opus 4.7 が新たに獲得した、視覚的な回路図を理解する能力に懸けたものでした。マザーボード上の電源経路をトレースするようモデルに依頼したとき、これは動くと確信したと彼は語ります。

「Wrench Board のボードビューが、ステップごとに点灯していくのを見ました。矢印が現れ、コンポーネントが指し示され、名前が浮かび上がる。その瞬間、このアイデアは成立すると理解しました」と彼は言います。

Wrench Board の次のフェーズは、このアプリを試してみたいエレクトロニクス修理職人や、自分の現場経験でツールを豊かにできる専門家のコミュニティを構築することです。彼の Claude クレジットは RepairMind、その最初のユーザーたち、そして現在進行中のインフラ全般に充てられます。

「このハッカソンは、修理工房から出てきた独学の人間でも、野心的なシステムを 5 日で出荷できることの証明です」と、エントリー時には「食いつなぐための仕事」に応募していた Alexis は語ります。「Claude Code は、出発点がどこであろうと、アイデアとそれを実行する忍耐力を持つ人間を増幅させてくれます」

**他のビルダーへのアドバイス：** ブレインストーミングを深く掘り下げ、モデルに反論しましょう。

Alexis は [Superpowers](https://claude.com/plugins/superpowers) を使っています。これは Claude に統合されたスキルフレームワークで、ブレインストーム → プランというステップを構造化し、ときには複数のブレインストームを並列に走らせて異なる方向の議論を進めます。彼は Claude Design から始め、組み込みのボタンでプロジェクトを直接共有して Claude Code に引き継ぎ、そしてモデルが「ノー」と言ってきたときには押し返します。

「ハッカソンの間、Claude は何度も、これは時間内に収まらないと私に言ってきました。でも実際には、時間はたっぷりあったのです」と彼は言います。「いずれにしてもやってみる、と伝える術を心得ておかなければなりません」

[*Wrench Board on GitHub*](https://github.com/Junkz3/wrench-board)

## 第 3 位：[Maieutic](https://maieutic.dev/)、Paula Vásquez-Henríquez

チリのコンセプシオンにある Universidad del Desarrollo でコンピュータサイエンスを教えている Paula Vásquez-Henríquez は、この 2 年間で、自分自身のコードを理解しないままテストに合格する学生が増えていると感じています。

「学生たちは今、AI を使ってコードを製造しますが、そのコードが何をしているのかをまるで分かっていません」と彼女は言います。「問題を正確に言語化することも、コーディング前にプランを立てることも、自分のコードを批判的に読み、自分の意図からどこでずれたのかに気づくことも、彼らは決して学びません。オートコンプリートは、彼らが問いを形にし終える前にすでに動くコードを差し出してきます。その結果、メタ認知のループ、つまりプログラマーを実際に作り上げる『思考についての思考』が、決して閉じないのです。彼らはコードを生成できるが、それについて推論できないまま卒業していきます」

学生と AI のインタラクションパターンを研究するために、現在 AI の博士課程に在籍中の Paula は、学生と教員の両方の視点からこの問題を解決すべく、ハッカソンに参加しました。

Maieutic は、学生に重要な場面で歩みを緩めさせるよう設計された IDE です。学生はコードを書き始める前に、自分のプログラムが何をすべきかを平易な言葉で記述しなければなりません。Claude は的を絞った明確化のための質問を投げかけ、有能なプログラマーが推測せずに実装できる程度に詳細な仕様になるまで、エディタをロックし続けます。

その後、学生は Python を書き始められますが、オートコンプリートはオフです。チャットパネルはリファレンス的な質問には直接答えますが、推論を要する質問には修正ではなく逆質問で応答し、学生の代わりに考えることを拒みます。

ツールの中核である Intent-Diff Review では、Claude が仕様と最終的なコードを比較し、それぞれの乖離を drift（ずれ）、revision（修正）、bug（バグ）に分類し、学生自身が問題を説明するよう促す中立的で非難の意図のない問いを浮かび上がらせます。

教員向けには、学生 1 人ごとに 1 行の認知サマリー（例：「仕様を 3 回書き直したが、まだ空入力を考慮していない」）が表示されるライブダッシュボードがあります。教員は個々の学生をクリックして、その学生と Claude の具体的なやり取りを追跡できます。Claude はさらにクラス全体を分析して、クラス内で共有されている誤解を特定・可視化し、教員がそのギャップを埋められるようにします。

ハッカソン終了後、ヒューストン大学の研究者から論文の共同執筆について連絡があり、Paula は賞のクレジットをツールのさらなる開発に充てる予定です。彼女は、ハッカソンの 1 週間で、問題を理解することと、それに対応するツールを出荷することの間にあったギャップが消失したことを実感したと言います。

「私はシリコンバレーではなく、チリのコンセプシオンで教育に携わる人間です」と彼女は語ります。「それでも 1 週間で動くフルスタックのプロダクトを出荷できたのは、ツールが私を本当に得意な役割に留まらせ、残りを引き受けてくれたからです。実際の問題に最も近い人が、その問題のために自分で直接ビルドできるようになったのです」

**他のビルダーへのアドバイス：** ビルドする前に考えましょう。

このプロジェクトは、Paula が自身の哲学を自ら実践したものでした。ビルドする前に仕様化する、という哲学です。「Maieutic が存在するのは、学生たちがいきなりコードに飛びつくからであり、私自身がそれをやらないと固く決めたからこそ、うまく作れたのです」と彼女は語ります。彼女は純粋な思考作業に 2 日間を割き、コードを 1 行も書く前にデザイン仕様と技術仕様を作成しました。

「あの 2 日間の仕様策定は、その時点では遅く感じました。ハッカソンではすぐに出荷を始めなければというプレッシャーが本当にあります。でも、その 2 日間こそが、残りの 1 週間を高速で進ませてくれたのです」と彼女は言います。

## Opus 4.7 の最もクリエイティブな活用：Virtual Puppet Theater、Rene Hangstrup Møller

Opus 4.7 の空間推論能力に興味を惹かれたフルスタックデベロッパーの Rene Hangstrup Møller は、Virtual Puppet Theater を構築しました。これはブラウザベースのアプリで、ウェブカメラの映像と音声を、ダイナミックでインタラクティブな人形劇に変えるものです。リアルタイムでアニメーションする人形がユーザーの動きをミラーリングする一方、もう一体の AI 駆動のコンパニオン人形がユーザーと掛け合いをします。音声プロンプトで風景を変えたり、3D の小道具をその場で生み出したりすることもできます。

Rene はパイプライン全体で Claude を使い、コンセプトの議論、プランニング、コードの記述を任せる一方で、ディレクション、アーキテクチャ、レビュー、意思決定は自分で担当しました。アプリは Bun、Vite、TypeScript をベースとしており、（WASM で動作する）MediaPipe のハンドトラッキングと Three.js を使って 3D の人形舞台を 60 fps でレンダリングしています。小さな WebSocket サーバーが Anthropic SDK 経由で Claude Opus 4.7 に接続し、AI 人形のセリフを駆動し、3D の小道具をオンザフライで生成します。音声は入力に Web Speech API、出力に ElevenLabs を使い（フォールバックとしてブラウザの音声合成も用意）、視覚的な出力は Opus の空間推論能力が処理しています。これはスクリーンショットベースのフィードバックループによって洗練されました。

Virtual Puppet Theater には、自由な遊び以外の目的はなく、Rene はこの受賞作品にプロダクトとしての計画はないと言います。彼にとってこれは学びと楽しみのためのものでした。「末っ子と一緒に試してみたら、彼は大興奮でした」と Rene は語ります。「人形と関わり、シーンを描写し、応答にクスクス笑う彼の姿を見たことが、私に必要な唯一のユーザー検証でした」

Virtual Puppet Theater のソースコードは MIT ライセンスのもと GitHub で公開されていると彼は付け加え、「さらに先に進めたい人がいればどうぞ」と語ります。

**他のビルダーへのアドバイス：** ハッカソンに参加するなら、デモ動画を作る時間も計画に入れましょう。

**‍**「3 分の動画を作るのは、思っているよりはるかに時間がかかります」と Rene は語ります。彼は Claude と Hyperframes を使って Virtual Puppet Theater の動画を作成・編集し、ハッカソンの締め切りギリギリで作業しました。「ハッカソンの Discord でも多くの人がこれを警告していて、それは正しかったです。次回は、最終日まるごとデモ制作のために確保するでしょう」

[*Virtual Puppet Theater on Github*](https://github.com/rhmoller/virtual-puppet-theater)

## 「Keep Thinking」賞：[MaestrIA](https://www.youtube.com/watch?v=rkH4AjoTL5Q)、Benjamin Torralbo

Benjamin Torralbo は、チリ・チロエの認定 *Maestro Mayor*（親方大工）である父 Juan Rodrigo Torralbo の傍らで修業しながら育ちました。「私の父には 30 年の技があり、UNESCO 登録の教会を修復してきましたが、それでもチリの制度の中では、他の何十万もの職人たちと同様に、目に見えない存在のままです」と Benjamin は語ります。「一方で、家の修理が必要な人々は、何が悪いのか、いくらかかるのか、誰に頼めばいいのか、自分が適正な料金を払っているのかが分からないのです」

彼のハッカソンプロジェクト [MaestrIA](https://maestriachile.cl/) は、ウェブアプリとしてこの両側を解決します。一般の人々に親方レベルの住宅修繕診断を提供する一方、熟練の職人には自分の専門性を示す手段を与えます。

MaestrIA を使うと、ユーザーは問題を撮影し、音声またはテキストで説明し、自分の位置情報を共有します。Claude は写真上にアニメーション付きのバウンディングボックスを重ねながら、推論をリアルタイムでストリーミングし、構造化された診断を提供します。何が壊れているか、材質、深刻度 1～5、プロジェクトの予算と所要時間の見積もりまで。続いてエージェントは、職種でフィルタリングされた近隣の親方の地図をレンダリングし、もう一体のエージェントが送信用の WhatsApp メッセージを下書きします。

MaestrIA の技術的な心臓部は、すべての診断に注入される JSON ファイルです。これには 17 の診断ルール、7 種類のチロエ固有の木材、地方の業界用語 16 語、19 の基準価格、そして職人がよく犯す 9 つのミスが含まれており、Benjamin が父親への何時間ものインタビューから蒸留したものです。システムプロンプトには手を加えないまま、このたった 1 つのファイルが、人間の親方の判断に対する評価スコアを 7 ポイント引き上げ（74% → 81%）、MaestrIA が単なる「木材の損傷」ではなく「アレルセ材の外壁に発生した湿気の上昇」を診断できるようにしているのです。

プログラミング経験ゼロの Benjamin は、自分の役割は現場監督として Claude の技術的な実行を監督することだったと語ります。「機能を書く前に、私は Claude Code に対して仕様、段階的なアクションプラン、そしてセキュリティモデル（プロンプトインジェクションへの入力サニタイズ、レート制限、オリジン検証、信頼の唯一の源としての Zod スキーマ）を設計させました」と彼は言います。「それから機能ごとに diff を 1 つずつレビューしました」

Benjamin は MaestrIA を、新築工事、ホームセンターとの連携、正式な見積、契約、レビュー、そして認定制度へと成長させたいと考えています。最終的には、大工、建築家、配管工、電気工、石工を含むそれぞれの職種に、固有の Maestro Mayor が組み込まれることになります。

彼の賞のクレジットは、アプリの開発、父親の会社の本番パイロットとしてのデジタル化、そして自身の技術的な成長に充てられます。「Claude Code は、プログラミング経験のないチロエの 20 歳に、自分の父親が実際に使えるソフトウェアを、そしてチリにいる父のような 28 万人の親方をも助けられるソフトウェアを作らせてくれます」と彼は語ります。「そしてそれは、これまで価値あるアイデアを持ちながらも形にする手段がなかった何百万もの人々に、扉を開くのです」

**他のビルダーへのアドバイス：** Eval が先、機能は後。

「私がやった中で最も重要だったのは、父が記録したグラウンドトゥルース付きの実例 12 件に対して、監査可能な 9 次元の eval を構築したことです」と Benjamin は言います。「私の直感ではなく、その eval が、何が機能していて何が機能していないかを教えてくれました。もう一度ハッカソンをやるなら、eval が最初のコミットになるでしょう」

## Claude Managed Agents 最優秀活用：[ARIA](https://www.youtube.com/watch?v=Hen24w2Jyz4&t=28s)、Idriss Benguezzou & Adam Hnaien

ほとんどの工場には、機械が出す音だけで、いつ壊れそうかを察知できる、あのベテラン技術者が一人はいるものです。Claude Managed Agents 最優秀活用賞を受賞したプロジェクト ARIA（Adaptive Runtime Intelligence）は、経験豊富な保全エンジニアの直感を、手頃でセットアップが速い AI システムに変え、工場の機械を継続的に監視し、トラブルが現れた瞬間にカスタム診断と修理プランを生成します。

ARIA を使うと、保全エンジニアはメーカーの PDF をアップロードし、平易な言葉で 4 つの校正用の質問に答えるだけで、15 分以内に工場全体がプロファイリングされます。そこから 5 体のエージェントがライブシグナルを監視します。エージェントが故障を検出するか、間もなく故障が起きると予測した場合には、コンポーネント、故障モード、緊急度、必要な部品、介入のタイミングを分析する作業指示を生成します。

このプロジェクトのビルダーは 2 人とも工場現場での産業経験があり、ハッカソンのチームメイト募集 Discord チャンネルで出会いました。Idriss Benguezzou はデータ／AI で修士号を持つフランスの産業ソフトウェアエンジニアで、しばらく前からこのアイデアとそのアーキテクチャの大部分を地図に落としていました。Claude Code とマルチエージェントワークフローに習熟した独学のエンジニアリング学生 Adam Hnaien は、ARIA が産業メンテナンスにとって価値あるソリューションであることを即座に見抜きました。

Idriss と Adam は、ハッカソンの 2 日目を丸ごとプランニングモードに費やし、GitHub Project ボード上であらゆるマイルストーン、課題、受け入れ基準を、最初の 1 行のコードを書く前にスコープしました。「私たちは M2 以降を 200% で進めたかったのです」と Adam は言います。「1 日のプランニングが、残りの 1 週間を即興ではなく実行に充てさせてくれました」

2 人とも、生のコード行の約 80% を Claude Code が書き、自分たちはドメインロジックとデザインの決定を手で行ったと見積もっています。Idriss は閾値評価、KB スキーマ、異常検知を担当しました。なぜなら、と彼は言います、「保全技術者が実際に何を見ているか、プロンプトでたどり着くことはできないからです」と。Adam は UX、ビジュアル言語、ARIA のコンステレーション・コンセプトを担いました。なぜなら、と彼は言います、「センスにプロンプトでたどり着くことはできないからです」と。

エージェントのインフラは Managed Agents が処理しました。「Claude Managed Agents がなければ、私たちは Anthropic がすでにホストしているインフラ、つまりサンドボックス化された Python 環境、安全な実行、セッションの永続化、MCP のディスパッチを構築するのに 1 週間を費やしていたでしょう」と Adam は語ります。「代わりに、そのインフラの周りでプロダクトを作り上げるのに 1 週間を使えたのです。それが、ARIA を 5 日で出荷するか、5 週間で出荷するかの差です」

ハッカソンの結果発表後、まさにこの問題に取り組んでいる企業が、このプロジェクトについて連絡してきました。Idriss は ARIA のエージェントアーキテクチャ、KB スキーマ、シグナルパイプラインを、自身の産業 IoT プラットフォームに取り込みます。彼のクレジットは、さらなる構築と実験に充てられます。Adam については、産業向けエージェント型 AI における機会の探索を続け、API クレジットを使って構築と実験を続ける計画です。
