*シリーズ「**How startups build with Claude**」では、スタートアップが AI によって自らの業界をどのように変革しているかを紹介しています。本記事では、Curative が Claude 上にエージェントの階層を構築し、2025 年の自社チームと比べておよそ 50 倍の速さで医療提供者（プロバイダー）との契約を締結するようになった事例を紹介します。*

[Curative](https://curative.com/) は雇用主向けに健康保険を販売しており、加入者が Baseline Visit（初回の健康診断）を受ければ、ネットワーク内の医療は自己負担額（copay）0 ドル、免責額（deductible）0 ドルで受けられます。Curative はもともと保険会社として始まったわけではありません。検査ラボのスタートアップとして出発し、社内の推計によれば、米国の COVID-19 検査全体の 10% を処理するまでになりました。その結果、国内のほぼすべての保険会社と取引するようになったのです。

患者が医療費を支払わない制度に慣れていたイギリス出身の創業者たちは、そこに非効率さを見いだし、予防に重点を置いた保険者（payer）をつくることにしました。しかし、全米規模のネットワークを構築することがどれほど難しいかを大幅に過小評価していたことに気づきます。

「スタートアップでは、ときに無知であることが良い方向に働きます。それが不可能だと知らないからです。そして進んでいくうちに、不可能を不可能でなくする方法を見つけるのです」と Curative の CEO である Fred Turner は語ります。「昨年は 2,100 件の契約を締結しました。前年の 2 倍です。それでも年 2,000 件のペースでは、構築に 30 年かかると気づきました。全米規模のネットワークがほんの一握りしかなく、そのすべてが約 30 年前に構築されたのには理由があるのです」

Curative は契約締結を加速する必要がありましたが、採用だけではこれほどの差を埋めることはできませんでした。

そこで生まれた解決策が Gwen です。Gwen は 1 件のプロバイダー案件を最初のアプローチから署名まで担当するエージェントで、その周囲には、料率のレビュー、メッセージのチェック、質問への回答、標準外の価格設定を人間にエスカレーションする役割を担う、より小さなエージェントが配置されています。

ここからは、彼らがどのようにこれを構築し、その過程で何がうまくいかなかったのかを紹介します。

## **Gwen：プロバイダー契約エージェント**

Gwen はインバウンドとアウトバウンドの両方のリードを担当します。Gwen の各実行は 1 つのプロバイダーだけを扱い、主に Claude Opus 上で動作するため、ほかの案件の内容が影響することはありません。

たとえば、ある診療所が Curative の Web サイトのフォームに記入すると、Gwen はその診療所を調査し、購入した請求データセットと、保険者に公開が義務付けられた価格透明性ファイルに基づいて、提案料率を添えて返信します。Gwen は交渉の助けとして、こうした市場料率のデータをプロバイダーに示します。

料率レビュアーは Sonnet 上で動作します。Gwen が標準の料率テンプレートを超えたい場合、その理由を書き出し、レビュアーがその料率が妥当かどうかを判断します。

「長い間、大きな承認キューがあり、Gwen はテンプレートを一定以上上回る料率にしたい場合には承認を得る必要がありました。しかし、時間をかけて制限を緩めていきました。Gwen にさらに大きな権限を与えるよりも、2 つ目のエージェントに料率をレビューさせるほうがうまくいったのです」と Fred は述べています。

Sonnet の料率レビュアーは Gwen のリクエストの約 3 分の 2 を承認し、標準外のものはすべて Fred の承認に回されます。

「私のところに来るリクエストは、大規模な医療グループからのものか、変わった要望を持つ人からのものです。エージェント主導の取り組みでなかったとしても、私のところに来ていたようなものです」と Fred は言います。

アウトバウンドの案件では、診療所が多忙なため、より粘り強さが求められます。14 通目のメールや 9 回目のファックスでようやく返信が来るプロバイダーもいます。

![Gwen が締結したプロバイダー契約の累計を示す折れ線グラフ。2026 年 3 月から 10 月にかけて 2 万 3,000 件を超えるまで増加しており、2026 年 7 月 24 日にファックスが追加されている。](https://assets.claude.com/81117dec18c16ca382f07795da2c7c1202546b9b.png)

画像は Curative の許可を得て使用しています。

Haiku 上で動作するジャッジが、送信前にすべての通信内容を読みます。これは、Gwen がどこまで料率を上げられるかについての社内メモを、プロバイダーに CC で送ってしまったことを受けて Curative が追加したものです。ブロックされたメッセージは理由とともに差し戻されるため、Gwen は書き直して再試行できます。

1 件の契約を完了するのにかかるトークンは約 2,000 万で、当初のコストのおよそ 10 分の 1 です。この効率性が、Curative の中核的な戦略の 1 つを可能にしています。それは、大手のネットワークに見過ごされがちだった小規模なプロバイダーと契約することです。

「エージェントは、相手が大規模な病院システムであっても、1 人で開業しているプロバイダーであっても、喜んで同じレベルの注意を払います」と Fred は説明します。「エージェントの視点からすれば、そのプロバイダーだけが唯一の関心事なのです」

交渉の間、Gwen は診療所からの修正案（redline）を Curative のポリシー文書と照らし合わせて確認し、その後 Python を書いて双方の変更を最終文書に統合します。

フォームの送信から署名まで、早ければ 1 時間ほどで完了します。契約が締結されると、別のクレデンシャリング（資格審査）エージェントがプロバイダーの免許を確認し、さらにエージェントがプロバイダーのデータと契約を登録して、請求をその契約に基づいて価格計算できるようにします。

Curative の契約チームは Gwen の導入以降、45 人から約 55 人に増え、1 人あたりの生産性は約 2.5 倍になりました。メンバーはコールドアウトリーチや書類作業を Gwen に任せ、見込みの高いリードは電話で引き継ぎます。Curative は Gwen が締結した案件についても契約チームに報酬を支払っているため、人間とエージェントが 1 つの目標を共有しています。

「人の仕事は、書類作業よりも関係づくりが中心になっていきます」と Fred は言います。

Fred はまた、契約の迅速化が小規模な診療所の独立維持にも役立つと考えています。「医療機関を開業して、ネットワークに加入しクレデンシャリングを受けるまでに 3 か月かかるとしたら、その 3 か月間はまったく報酬が入らないのです」と彼は語ります。

Curative のエージェントは Gwen だけではありません。同じく Opus ベースのエージェントである Brad は、主にブローカーを通じて Curative のプランを雇用主に販売する手助けをしています。Brad は見積もりごとにブローカーへのフォローアップを行い、アンダーライターがかつて手作業で整理していたスプレッドシートから従業員データを抽出することで、アンダーライターの業務を迅速化しています。

人間とエージェントのチームによって、Curative は現在、メールやファックスで寄せられた請求に関する異議申し立てに対し、その請求に固有の内容の書面で 30 分以内に回答できるようになりました。「請求に関する異議申し立てへの回答には以前は約 90 日かかっていましたが、今ではメールやファックスで 30 分以内に回答しています」と Fred は言います。「ほとんどの保険者は、差し込み印刷で組み合わせたテンプレート群を使っています。それではプロバイダーはまったく満足しません。たいていの場合、テンプレートでは実際に何が起きているのかを説明できないからです。今では、プロバイダーは個々の請求の詳細、何が起きているのか、そしてその理由を説明するカスタマイズされた書面を受け取れます」

同社のすべてのエージェントは、独自開発の請求、事前承認、財務システムの上で動いています。これらのシステムは、今年 13 人のエンジニアが Claude Code を使って再構築したものです。チームはかつて、請求システムの構築だけで 100 エンジニア年かかると見積もっていました。

「私たちは [これらのエージェントを] 請求システムに後付けで接続しようとしているわけではありません」と Fred は言います。「請求システムは AWS 上で動く Python で、MCP も API も備えています。そして Claude が書いたものなので、Claude はそれを理解しているのです」

## **人と交渉するエージェントの構築から Curative が学んだこと**

人と交渉するエージェントの構築について、Curative のチームが学んだことは次のとおりです。

- **1 つの汎用ツールから始める。**「最初は『ツールを用意しよう』と考えていましたが、それはあまりうまくいきませんでした。修正案の作成（redlining）はかなり複雑だからです」と Fred は言います。「最もうまくいったのは、モデルに Python を実行するというツールを 1 つだけ与え、docx ライブラリで修正作業をすべて行わせる方法でした。見事に機能しています」
- **相手が使うチャネルで対応する。**ファックスツールの導入によって Gwen の成約率は 2 倍以上になりました。今では多くのプロバイダーが、印刷したファックスに手書きで書き込み、ファックスで返送してきます。「相手がいる場所に合わせるということです」と Curative の CTO である Isaac Turner は言います。「もちろんメールも持っていますが、本当に使い慣れているのはファックスなのです」
- **各実行を分離する。**Gwen の 1 回の実行は 1 つのプロバイダーだけを扱い、案件をまたいだメモリは保持しません。一方、Curative の営業エージェントである Brad はメモリを保持しており、これは機能していますが注意が必要です。「誤ったメモを作ってしまい、消去できない悪い記憶を抱えたまま破滅的なループ（doom loop）に陥ることがあります」と Fred は指摘します。
- **実行の外側からシステムを改善する。**Fred は数日ごとに Claude Code に同じプロンプトを与えています。直近 1 万件の実行をサンプリングし、おかしな点にフラグを立て、それを修正する PR を作成する、というものです。「改善ループは、大量の過去の会話に対して Claude Code を走らせ、どうすればもっと良くできたかを問うことから生まれます」と彼は言います。
- **まずは PHI から離れた場所で実験する。**長い間、Gwen は保護対象医療情報（PHI）へのアクセスを禁止されていたため、初期のミスはリスクの低い環境で起きていました。現在エージェントが PHI を扱う場面では、バックエンドの制御によって会話に入る情報が制限され、エージェントの活動は監査のためにログに記録されています。「まずそちらでやり方を学び、それを PHI の領域に移したのです」と Fred は言います。ベンダーが PHI を扱う前に HIPAA で義務付けられている契約である事業提携契約（BAA）の締結も容易になりました。「特に Anthropic は、最新サービスの HIPAA 準拠版を非常に迅速に提供してくれています」と Isaac は言います。「規制の厳しい分野であるにもかかわらず、こうした新しいテクノロジーを非常に迅速に導入できています」
- **エージェントが自発的に始めることを観察し、自社のリスクプロファイルに合っているかを確認する。**プロバイダーから社内共有用のチラシを求められたとき、Gwen はそれを指示するポリシーがないにもかかわらず、Python ツールを使ってチラシを作成しました。また、ネットワーク内の診療所の受付が加入者を断ったときには、Gwen はその診療所にスタッフの教育を依頼し、その後加入者が受診できたことを確認しました。

## **Curative の今後**

Curative は次に、ケアナビゲーションにエージェントを導入し、加入者のガイドやコーチングを担う 130 人のスタッフの対応範囲を広げることを計画しています。

Fred は、プロバイダー側にもエージェントが登場すると予想しています。請求に関する異議申し立てのかなりの割合は、すでにエージェントによって書かれているように見受けられ、彼はプロバイダーがエージェントを使って契約交渉を行うようになることを期待しています。「市場の均衡価格というものがあり、それを早く見つけられれば、誰もが医療の提供に専念できるのです」と彼は語ります。

| Curative チームのベストプラクティス |
| --- |
| エージェントには最初にどれくらいの権限を与えるべきか？ | エージェントが対応できると思うよりも少なく。Gwen は当初、テンプレートを上回るあらゆる料率について人間の承認キューを通していました。Curative は段階的に、またより決定論的な判断から制限を緩め、その後料率レビュアーを追加しました。レビュアーが承認しないものは、引き続き Fred が承認しています。 |
| エージェントが間違えたらどうなるか？ | それを想定して計画し、代替手段と比較することです。「基準は完璧であることではありません」と Isaac は言います。「基準は、もし 1,000 人の人間が契約を締結していたら、後悔するようなミスをどれだけ犯すか、ということです」 |
| 何十万件ものメッセージをどう監査するか？ | すべてをログに記録し、すべての送信メッセージにジャッジエージェントを配置し、Claude Code に実行をサンプリングさせることです。 |

*今すぐ [Claude Platform](https://platform.claude.com) で構築を始めましょう。*
