Claude Platform で、メッセージスレッド（message threads）がパブリックベータとして利用可能になりました。メッセージスレッドを使えば、エージェントはターンごとに会話履歴全体を再送信する必要がなくなり、長時間にわたるセッションのレイテンシを削減できます。

### メッセージスレッドの仕組み

コーディングエージェントは 1 つのセッションで数百ものリクエストを行うことがあり、そのたびにそれまでのすべてのメッセージとツール結果を再送信しています。会話が数十万トークン規模に達すると、そのすべてを再送信することで、Claude が応答を開始するまでに余分な時間がかかります。メッセージスレッドを使えば、エージェントは前回のターン以降に追加された内容だけを送信すればよいため、最初のトークンが返るまでの時間（TTFT）を短縮できます。

ほとんどの Claude Code ユーザーに対してメッセージスレッドがデフォルトで有効化された結果、50 万〜100 万トークンのリクエストでは TTFT の中央値が約 35% 短縮されています。

メッセージスレッドを使うには、Messages API のリクエストに `thread` パラメータを追加します。最初のリクエストには会話全体を含め、これによってスレッドが開始されます。以降のリクエストには、新しいメッセージと直前のレスポンスの ID だけを含めます。ターンとターンの間、各スレッドは暗号化された状態でメモリ上に保持され、ディスクに書き込まれることはありません。スレッドは最後のリクエストから 5 分後に失効し、その後はクライアントが会話全体を再送信して新しいスレッドを開始します。メッセージスレッドによって各リクエストは小さくなりますが、Claude は毎ターン会話全体を読み込むため、トークン使用量は変わりません。

メッセージスレッドは、レイテンシが重要となるアクティブなセッションに最適です。たとえば次のようなケースです。

- **長時間稼働するコーディングエージェント**：ツール結果やファイル編集のたびに会話が増えていきます。
- **コンピュータ操作（Computer use）エージェント**：スクリーンショットをターンごとに再アップロードする代わりに、スレッド内に保持しておけます。
- **ドキュメントや画像を多用するワークフロー**：リクエストを小さくできます。

エージェントが抱えるコンテキストが大きいほど、メッセージスレッドによる TTFT の短縮効果は大きくなります。

### はじめに

メッセージスレッドは現在、ネイティブの Claude Platform のほか、Claude Platform on AWS、Claude in Microsoft Foundry、Claude Models on Google Cloud（Anthropic managed）でパブリックベータとして利用可能です。通常の Claude のトークン料金と既存のレート制限が適用されます。利用を開始するには[ドキュメント](http://platform.claude.com/docs/en/build-with-claude/message-threads)をご覧ください。
