毎日、何百万ものユーザーが、独自のコードから機密性の高い事業戦略に至るまで、センシティブな情報を Claude に[託して](https://trust.anthropic.com/)います。Anthropic では、ユーザーのこの信頼が正当なものであること、さらに言えば、その信頼が暗号学的に保証されたものとなるよう、新しい技術の研究と構築に取り組んでいます。

「暗号学的に保証される」とはどういう意味でしょうか。[Pattern Labs](https://www.patternlabs.co/) と共同で公開した[新しいレポート](https://assets.anthropic.com/m/c52125297b85a42/original/Confidential_Inference_Paper.pdf)では、機密推論（Confidential Inference）の仕組みについて説明しています。機密推論とは、暗号化されたデータを処理し、そのデータが自らの信頼性を証明できるサーバーの内部でのみ読み取り可能であることを示すために使用できる、一連のツールです。これらのツールを採用する主な理由は 2 つあります。

- モデルの重みのセキュリティ: 機密推論は、Claude のようなフロンティアモデルを、ますます高度化する脅威アクター（RAND の最近のレポート [Securing AI Model Weights](https://www.rand.org/pubs/research_reports/RRA2849-1.html) で説明されているようなもの）から守るための、より広範な取り組みの一要素として活用できます。
- ユーザーのセキュリティ: 機密推論を使えば、センシティブなユーザーデータが秘匿されていることを証明できます。

この記事と付随する[レポート](https://assets.anthropic.com/m/c52125297b85a42/original/Confidential_Inference_Paper.pdf)を公開するのは、機密推論とは何か、そしてそれがユーザーにどのようなメリットをもたらしうるかを説明するためです。また、関連するシステムのセキュリティについて私たちがどう考えているかも共有したいと考えています。これは議論のきっかけとするための研究のスケッチにすぎません。この取り組みはまだ初期段階にあり、将来私たちが提供しうる具体的な設計や機能へとどのように発展していくかを予測するには時期尚早です。

以下のセクションでは、機密推論の実装に関する技術的な詳細の一部を紹介します。重要なポイントは、センシティブなデータが、処理が必要となるまさにその瞬間を除いてあらゆる場所で暗号化されたままとなり、しかもその瞬間でさえ、厳しく制限された検証可能な環境の内部でのみ扱われることを確実にするためのシステムを、私たちが構築しているということです。

## 推論サービス

機密推論の根底にある指針は、センシティブなデータは処理される時点を除いて暗号化されたままであるべきだ、というものです。これを徹底するために、私たちはコンフィデンシャルコンピューティング（confidential computing）の確立された手法を用います。具体的には、ソフトウェアのセキュリティを証明（アテステーション）する信頼の連鎖（chain of trust）を構築し、そのアテステーションを使って、どのソフトウェアが暗号鍵を使用できるかについてのルールを厳密に適用します。

ユーザーデータについては、センシティブな平文（つまり、暗号化やその他の方法で一切秘匿されていないテキスト）を扱う必要がある箇所が 2 つあります。

- API サーバー。このサーバーはプロンプトを処理してトークンに変換し、Claude API リクエストの背後にあるロジックの大部分を実行します。
- 推論サーバー。このサーバーはハードウェアアクセラレータ上で Claude の「頭脳」を動かし、プロンプトから補完トークンを生成します。

モデルの重みについては、センシティブなデータを受け取るのは推論サーバーだけです。

この記事では推論サーバーに焦点を当てます。API サーバーのセキュリティも同様に重要ですが、ここで説明しようとしている範囲を超えています。すべてのアクセラレータがまだコンフィデンシャルコンピューティングを完全にはサポートしていないため、私たちは、信頼された環境内で実行できる小さくセキュアな「モデルローダー兼インボーカー」の上に推論サーバーを実装する方法を検討しています。このローダープログラムが担うのは、いくつかの単純な仕事です。

- 暗号化されたデータを受け取って復号し、アクセラレータに送る。
- アクセラレータに対する呼び出しを実行し、暗号化した結果を呼び出し元に返す。

復号されたデータにアクセスできるのは「信頼された」ローダーだけです。システムの残りの部分は「信頼されていない」ものですが、ローダーにリクエストを送ることはできます。

私たちは自社の実装として、この設計に基づくシステムの開発に取り組んでいます。この実装では、推論サーバーの大部分は「信頼されていない」側で動作します。そこでは頻繁に変更が加えられる可能性がありますが、その変更がシステム全体のセキュリティに影響を与えることはありません。小さな信頼されたローダーは、ハイパーバイザーによって分離された別の仮想マシン上で動作します。ローダーは推論サーバーに対して、モデルアーキテクチャの詳細に依存しない「仮想アクセラレータ」として振る舞います。この「仮想アクセラレータ」は、セキュアな継続的インテグレーション（CI）サーバーによって署名されたプログラムのみを受け付けます。これにより、実行されるコードはすべて複数のエンジニアによってレビュー済みであることが保証されます。

最終的な狙いは、ローダーが正しく実行されている限り、*システムの他の部分が何をしようとも*機密性の要件が満たされるようにすることです。したがって、ローダーが正しく実行されていることを確立することが極めて重要になります。

## 信頼された環境

レポートでは、ローダーが以下の特定の機能を備えたコンフィデンシャルコンピューティング環境で動作することを説明しています。

1. 他のワークロードからハードウェアによって分離された、暗号化メモリ
2. 無効化されたデバッグ機能
3. 正しいコードが実行されていることの暗号学的な証明

(1) は、ある種の物理的攻撃や悪意のあるハイパーバイザーから保護します。ただし、暗号化されたホストメモリをアクセラレータと共有するために必要な機能は、現時点ではまだ十分に確立されていません。私たちはこのギャップを埋める取り組みを続けますが、それまでの間は、物理的なデータセンターおよびハイパーバイザーソフトウェアにおけるセキュリティの維持を、コンピュートプロバイダーに頼ることになります。

(2) と (3) は、トラステッドプラットフォームモジュール（TPM）を信頼の起点（root of trust）として用いる、広くサポートされたコンフィデンシャルコンピューティングの手法によって実現できます。TPM はブートプロセスの各段階を計測し、最終結果を表すハッシュを報告します。このハッシュが、ローダーサーバーが想定どおりに分離されていること、署名とレビューを経たコードを実行していること、そして関連するデバッグ機能を無効化する設定になっていることのアテステーションとなります。鍵サーバー（keyserver）はこの証明を検証し、受信者が自らのセキュリティを証明した場合にのみ復号鍵を払い出すことができます。

ある環境が「信頼された」ものかどうかの判断は、最終的には鍵サーバーに委ねられます。私たちはまた、信頼されたコードを第三者が検証し、独立した鍵サーバーを管理するようなコンフィデンシャルコンピューティングのモデルについても検討しています。これにより、個々のデータに対してより強力な機密性の保証を提供できる可能性があります。

## 今後の方向性

フロンティアモデルの能力が高まるにつれ、セキュアなローダー層にさらなる安全策を組み込む必要が出てくるかもしれません。たとえば、平文のモデルの重みを保持するサーバーに対して[送信帯域幅の制限（egress bandwidth limitations）](https://www.anthropic.com/news/activating-asl3-protections)のレイヤーを追加することや、推論の実行に安全性分類器（safety classifier）による署名を必須とすることなどが考えられます。この機密推論のモデルを提示することで、Anthropic の環境のセキュリティとユーザーデータの機密性を継続的に確保するために、どのような追加機能を検討する価値があるかについての議論が生まれることを期待しています。

## まとめ

この研究は、モデルの重みを守り、ユーザーデータを保護するための私たちの継続的な取り組みを前進させるものです。このモデルを用いてユーザーのリクエストを保護することで、顧客データが復号されるのは、ハードウェアに基づく強化されたセキュリティ制御を備えたコンテキストの中だけになるように設計されています。

- リクエストは、Anthropic のサーバーに到達する前の時点で暗号化されます。
- リクエストが API サーバーに到達すると、復号・処理されたうえで再暗号化されてから、次へと渡されます。
- 推論サーバーはリクエストを暗号化された形で扱い、リクエストが復号されるのは信頼されたローダーに送られたときだけです。
- 補完結果はローダーを出る前に暗号化され、API サーバーを経由して呼び出し元に返されます。

モデルの重みについては、話はもっと単純です。重みは暗号化して保存し、ローダーで復号し、そこから外に出さないようにできます。

（[すでに対応している](https://developer.nvidia.com/blog/confidential-computing-on-h100-gpus-for-secure-and-trustworthy-ai/)ところを除く）ハードウェア設計者の皆さんには、チップにコンフィデンシャルコンピューティングを組み込むことをぜひ検討していただきたいと考えています。アクセラレータにハードウェアの信頼の起点が備わっていれば、この種のシステムの信頼境界を大幅に縮小できます。
